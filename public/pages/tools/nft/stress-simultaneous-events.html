Guia do especialista

Pergunta que este cenário responde: a página processa muitos eventos ao mesmo tempo sem perder nenhum e sem travar? É o caso de notificações em tempo real, websockets e dashboards ao vivo.

Hipótese de teste

Com 100 eventos a cada 10 ms, a página precisa de ~1 s para processar tudo. Reduzindo o intervalo para 0, os eventos se acumulam numa fila e a interface pode congelar enquanto ela esvazia.

O que medir

Eventos processadosIguais aos disparados, na ordem certa.
Eventos por segundoVazão sustentada.
Atraso de processamentoTempo entre disparo e exibição de cada evento.
Tarefas longasAgrupar atualizações em um frame evita travamentos.

Critério de aceite (exemplo)

Com 100 eventos e intervalo de 10 ms, todos aparecem no log e nenhuma tarefa passa de 50 ms.

Armadilhas comuns

  • Atualizar o DOM a cada evento. Agrupar com requestAnimationFrame é bem mais barato.
  • Não verificar a ordem: em sistemas reais, eventos podem chegar fora de ordem.
  • Testar só a quantidade e não o estado final mostrado ao usuário.

Automatize com Playwright

Usa a Long Tasks API para provar que a thread principal não travou.

import { test, expect } from '@playwright/test';

test('100 eventos sem tarefas longas', async ({ page }) => {
  await page.goto('/pages/tools/nft/stress-simultaneous-events.html');
  await page.evaluate(() => {
    (window as any).longTasks = 0;
    new PerformanceObserver((l) => ((window as any).longTasks += l.getEntries().length))
      .observe({ type: 'longtask', buffered: false });
  });
  await page.fill('#event-count', '100');
  await page.fill('#event-interval', '10');

  await page.click('#start-events');
  await expect(page.locator('#metric-events')).toHaveText('100', { timeout: 20_000 });
  expect(await page.evaluate(() => (window as any).longTasks)).toBe(0);
});

Como Testar Este Cenário

  • Performance: Observe se a aplicação consegue processar todos os eventos
  • CPU: Monitore o uso de CPU durante o disparo de eventos
  • Throttling: Verifique se há throttling ou debounce implementado
  • Memória: Observe se há vazamentos de memória com muitos eventos
  • Responsividade: Teste se a interface continua responsiva
