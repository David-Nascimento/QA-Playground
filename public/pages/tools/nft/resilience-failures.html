Guia do especialista

Pergunta que este cenário responde: quando parte das chamadas falha, o sistema se recupera sozinho e avisa o usuário de forma honesta?

Hipótese de teste

Com 30% de falha e até 3 retries, a chance de uma operação falhar em todas as 4 tentativas é 0,3⁴ ≈ 0,8%. Logo, quase todas devem terminar com sucesso. Com 0 retries, ~30% falham.

O que medir

Taxa de sucesso finalDepois dos retries. Compare com 1 − taxa_de_falha^(retries+1).
Tentativas por operaçãoMédia e máximo. Se o máximo passar do limite, há bug.
Mensagem ao usuárioFalha definitiva deve explicar o que aconteceu e o que fazer.
Estado após falhaNada pela metade: a interface volta a um estado consistente.

Critério de aceite (exemplo)

Com falha de 30%, 10 operações e 3 retries, a taxa de sucesso final fica acima de 90% na maioria das execuções. Cada tentativa leva de 0,5 s a 1,5 s, então reserve até um minuto para a rodada completa.

Armadilhas comuns

  • Aleatoriedade: sem fixar a semente, o teste fica flaky. Em CI, valide faixas (≥ 90%) ou controle o gerador.
  • Tratar todo erro como temporário. 4xx (dado inválido) não deve ser repetido; 503 e timeout, sim.
  • Esconder a falha: "tente de novo mais tarde" é melhor que um carregamento infinito.

Automatize com Playwright

Como o resultado é aleatório, o teste valida uma faixa e repete o cenário algumas vezes.

import { test, expect } from '@playwright/test';

test('retries elevam a taxa de sucesso acima de 90%', async ({ page }) => {
  test.setTimeout(90_000);
  await page.goto('/pages/tools/nft/resilience-failures.html');
  await page.locator('#failure-rate').fill('30');
  await page.fill('#attempt-count', '10');
  await page.locator('#auto-retry').check();
  await page.fill('#max-retries', '3');

  await page.click('#start-test');
  await expect(page.locator('#metric-total')).toHaveText('10', { timeout: 80_000 });

  const taxa = parseFloat((await page.textContent('#metric-rate')) ?? '0');
  expect(taxa).toBeGreaterThanOrEqual(90);
});

Como Testar Este Cenário

  • Resiliência: Observe como o sistema lida com falhas e se recupera
  • Retry: Teste diferentes configurações de retry automático
  • Fallback: Verifique se há mecanismos de fallback implementados
  • Métricas: Anote taxas de sucesso para diferentes configurações de falha
  • Comportamento: Observe mensagens de erro e feedback ao usuário
