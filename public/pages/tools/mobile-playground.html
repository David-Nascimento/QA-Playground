Configuração Android para Automação

Primeiros Passos na Automação Mobile Android

O que você vai aprender:

  • Como configurar seu ambiente de desenvolvimento
  • Como instalar todas as ferramentas necessárias
  • Como criar seu primeiro projeto de automação
  • Como escrever e executar testes mobile

Checklist Inicial

Passo 1: Instalar Node.js

Necessário para instalar o Appium. Baixe em nodejs.org

Verificar instalação:
node --version
npm --version

Passo 2: Instalar Java JDK

Requerido para executar Appium e testes Java. JDK 11 ou superior (o java-client 9 exige Java 11; prefira uma versão LTS como 17 ou 21).

Verificar instalação:
java -version

Passo 3: Instalar Android Studio

Fornece Android SDK e emuladores. Baixe em developer.android.com

Passo 4: Instalar Appium

Framework de automação mobile multiplataforma.

npm install -g appium

# 1. Iniciar Appium Server
appium

# 2. Verificar dispositivos conectados
adb devices

# 3. Executar seus testes
# (depende da linguagem escolhida)

# 4. Ver logs e resultados
# Appium mostra logs no terminal

Dica para Iniciantes

Siga os passos na ordem: Instalação → Preparar Projeto → Capabilities → Exemplos. Não pule etapas, cada uma é importante para o sucesso da automação.

Guia Completo de Instalação Android

1. Instalar Node.js e npm

# Windows: Baixar instalador em nodejs.org
# macOS: Usar Homebrew
brew install node

# Linux (Ubuntu/Debian)
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt-get install -y nodejs

# Verificar instalação
node --version  # Deve mostrar v18.x ou superior
npm --version   # Deve mostrar 9.x ou superior

2. Instalar Java JDK

# Windows: Baixar JDK 17+ do Oracle ou usar OpenJDK
# macOS: Usar Homebrew
brew install openjdk@17

# Linux (Ubuntu/Debian)
sudo apt-get update
sudo apt-get install openjdk-17-jdk

# Configurar JAVA_HOME (Windows)
# Variáveis de Ambiente → JAVA_HOME = C:\Program Files\Java\jdk-17

# Configurar JAVA_HOME (macOS/Linux)
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
echo 'export JAVA_HOME=$(/usr/libexec/java_home -v 17)' >> ~/.zshrc

# Verificar
java -version
echo $JAVA_HOME

3. Instalar Android Studio

Passo a passo:

  1. Baixe Android Studio em developer.android.com/studio
  2. Execute o instalador e siga o assistente
  3. Durante a instalação, selecione:
    • Android SDK
    • Android SDK Platform
    • Android Virtual Device (AVD)
    • Performance (Intel HAXM) - se disponível
  4. Após instalação, abra Android Studio → More Actions → SDK Manager
  5. Instale:
    • Android SDK Platform-Tools
    • Android SDK Build-Tools
    • Android Emulator
    • Pelo menos uma versão do Android (recomendado: Android 11 ou 12)

4. Configurar Variáveis de Ambiente

# Windows (PowerShell como Administrador)
[System.Environment]::SetEnvironmentVariable("ANDROID_HOME", "C:\Users\SeuUsuario\AppData\Local\Android\Sdk", "User")
[System.Environment]::SetEnvironmentVariable("Path", $env:Path + ";$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\tools", "User")

# macOS/Linux
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/tools
echo 'export ANDROID_HOME=$HOME/Library/Android/sdk' >> ~/.zshrc
echo 'export PATH=$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/tools' >> ~/.zshrc

# Verificar instalação
adb version
echo $ANDROID_HOME

5. Instalar Appium e Drivers

# Instalar Appium globalmente
npm install -g appium

# Instalar driver UiAutomator2 para Android
appium driver install uiautomator2

# Verificar instalação
appium --version
appium driver list

# Diagnosticar o ambiente (Appium 2: o doctor vem com cada driver)
appium driver doctor uiautomator2

6. Criar e Configurar Emulador Android

  1. Abra Android Studio
  2. Tools → Device Manager
  3. Create Device
  4. Escolha um dispositivo (ex: Pixel 5)
  5. Escolha uma imagem do sistema (ex: Android 11 - API 30)
  6. Finalize a criação
  7. Inicie o emulador para testar
# Listar emuladores disponíveis
emulator -list-avds

# Iniciar emulador via linha de comando
emulator -avd NomeDoEmulador

# Verificar dispositivos conectados
adb devices

Verificação Final

Execute estes comandos para confirmar que tudo está instalado:

node --version      # ✓ Node.js instalado
java -version       # ✓ Java instalado
adb devices         # ✓ Android SDK configurado
appium --version    # ✓ Appium instalado
appium driver list  # ✓ UiAutomator2 deve aparecer

Próximos Passos

Após preparar o projeto, você está pronto para configurar as Capabilities e escrever seus primeiros testes. Veja a seção "Capabilities" para entender como configurar a conexão com dispositivos Android.

Capabilities Android - Guia Completo

Capabilities são configurações que informam ao Appium como se conectar e interagir com seu dispositivo Android. Pense nelas como "instruções" para o Appium.

Capabilities Obrigatórias

platformName: "Android"

Obrigatório. Define a plataforma. Sempre "Android" para dispositivos Android.

automationName: "UiAutomator2"

Obrigatório. Driver de automação. UiAutomator2 é o padrão moderno para Android.

Capabilities Importantes

platformVersion: "11.0"

Versão do Android. Descubra com: adb shell getprop ro.build.version.release

deviceName: "Android Emulator"

Nome do dispositivo. Pode ser qualquer nome descritivo. Listar dispositivos: adb devices

udid: "emulator-5554"

ID único do dispositivo. Obtido com adb devices. Necessário quando há múltiplos dispositivos.

Capabilities para Aplicativos

app: "/path/to/app.apk"

Caminho completo para o arquivo APK. Use caminho absoluto ou relativo ao projeto.

appPackage: "com.example.app"

Package name da aplicação. Descubra com: aapt dump badging app.apk | grep package

appActivity: "com.example.app.MainActivity"

Activity principal. Descubra com: adb shell dumpsys window | grep mCurrentFocus

Capabilities de Comportamento

noReset: false

Se true, não limpa dados do app entre testes. Útil para testes que dependem de estado anterior.

fullReset: false

Se true, desinstala e reinstala o app completamente. Use apenas quando necessário.

autoGrantPermissions: true

Concede automaticamente todas as permissões solicitadas pelo app.

  • Sempre use caminhos absolutos para o APK
  • Verifique o package e activity antes de executar testes
  • Use noReset: false para garantir estado limpo entre testes
  • Para testes em navegador, use browserName: "Chrome" em vez de app

Exemplos Completos de Código Android

Exemplos práticos e completos para começar a automação Android. Cada exemplo inclui configuração, interações básicas e boas práticas.

import io.appium.java_client.android.AndroidDriver;
import io.appium.java_client.android.options.UiAutomator2Options;
import org.openqa.selenium.By;
import org.openqa.selenium.support.ui.WebDriverWait;
import org.openqa.selenium.support.ui.ExpectedConditions;
import java.net.URL;
import java.time.Duration;

public class AndroidTest {
    private static AndroidDriver driver;
    
    public static void main(String[] args) {
        // Configurar capabilities
        UiAutomator2Options options = new UiAutomator2Options();
        options.setPlatformName("Android");
        options.setPlatformVersion("11.0");
        options.setDeviceName("Android Emulator");
        options.setAutomationName("UiAutomator2");
        options.setApp("/caminho/completo/app.apk");
        options.setAppPackage("com.example.app");
        options.setAppActivity("com.example.app.MainActivity");
        options.setNoReset(false);
        options.setAutoGrantPermissions(true);
        
        // Inicializar driver
        driver = new AndroidDriver(
            new URL("http://localhost:4723"), 
            options
        );
        
        try {
            // Exemplo: Encontrar elemento por Resource ID
            WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
            wait.until(ExpectedConditions.presenceOfElementLocated(
                By.id("com.example.app:id/loginButton")
            )).click();
            
            // Exemplo: Preencher campo de texto
            driver.findElement(By.id("com.example.app:id/username"))
                .sendKeys("usuario@exemplo.com");
            
            // Exemplo: Verificar se elemento está visível
            boolean isVisible = driver.findElement(
                By.id("com.example.app:id/welcomeMessage")
            ).isDisplayed();
            
        } finally {
            // Sempre fechar o driver
            driver.quit();
        }
    }
}
from appium import webdriver
from appium.options.android import UiAutomator2Options
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# Configurar capabilities
options = UiAutomator2Options()
options.platform_name = "Android"
options.platform_version = "11.0"
options.device_name = "Android Emulator"
options.automation_name = "UiAutomator2"
options.app = "/caminho/completo/app.apk"
options.app_package = "com.example.app"
options.app_activity = "com.example.app.MainActivity"
options.no_reset = False
options.auto_grant_permissions = True

# Inicializar driver
driver = webdriver.Remote("http://localhost:4723", options=options)

try:
    # Exemplo: Encontrar elemento por Resource ID
    wait = WebDriverWait(driver, 10)
    login_button = wait.until(EC.presence_of_element_located((
        By.ID, "com.example.app:id/loginButton"
    )))
    login_button.click()
    
    # Exemplo: Preencher campo de texto
    username_field = driver.find_element(By.ID, "com.example.app:id/username")
    username_field.send_keys("usuario@exemplo.com")
    
    # Exemplo: Verificar se elemento está visível
    assert driver.find_element(By.ID, "com.example.app:id/welcomeMessage").is_displayed()
    
finally:
    # Sempre fechar o driver
    driver.quit()

Boas Práticas nos Exemplos

Sempre use esperas explícitas

Elementos mobile podem demorar para aparecer. Use WebDriverWait em vez de Thread.sleep().

Prefira Resource ID

Resource ID é mais estável que XPath em Android. Use sempre que possível.

Sempre feche o driver

Use try/finally ou ensure para garantir que o driver seja fechado mesmo em caso de erro.

Trate exceções

Mobile pode ter mais falhas que web. Trate exceções adequadamente e adicione logs.

Diferenças: Automação Web vs Mobile

Automação mobile tem diferenças fundamentais em relação à automação web. Entender essas diferenças é crucial para o sucesso.

1. Seletores e Localização de Elementos

Web (Selenium)

  • ID, Class, Name
  • XPath, CSS Selectors
  • Link Text, Partial Link
  • Tag Name

Mobile (Appium)

  • ID (resource-id)
  • Accessibility ID
  • XPath (limitado)
  • Class Name
  • Android UIAutomator
  • iOS Predicate

2. Interações e Gestos

# WEB: Cliques simples
driver.findElement(By.id("button")).click()

# MOBILE (Appium 2 + UiAutomator2): gestos prontos do driver
# TouchAction está obsoleto desde o java-client 8: use estes comandos ou W3C Actions
# Tap (toque simples)
driver.executeScript("mobile: clickGesture", Map.of("x", 500, "y", 500));

# Swipe (deslizar para cima dentro de uma área)
driver.executeScript("mobile: swipeGesture", Map.of(
    "left", 100, "top", 500, "width", 600, "height", 800,
    "direction", "up", "percent", 0.75));

# Long Press (toque longo)
driver.executeScript("mobile: longClickGesture", Map.of(
    "elementId", ((RemoteWebElement) element).getId(), "duration", 1000));

# Pinch/Zoom (pinçar)
driver.executeScript("mobile: pinchOpenGesture", Map.of(
    "elementId", ((RemoteWebElement) element).getId(), "percent", 0.75));

3. Contextos e WebViews

Web: Sempre trabalha em um único contexto (a página web).

Mobile: Pode ter múltiplos contextos:

  • NATIVE_APP: Contexto nativo da aplicação
  • WEBVIEW: Contexto web dentro do app (como um iframe)
# Listar contextos disponíveis
Set<String> contexts = driver.getContextHandles();

# Alternar para WebView
driver.context("WEBVIEW_com.example.app");

# Voltar para Native
driver.context("NATIVE_APP");

4. Esperas e Sincronização

Web

  • WebDriverWait
  • ExpectedConditions
  • Implicit Wait
  • Page Load Timeout

Mobile

  • WebDriverWait (similar)
  • Espera por Activity
  • Espera por Package
  • Espera por Elemento
  • Timeout de instalação

5. Instalação e Gerenciamento de Apps

# WEB: Não aplicável

# MOBILE: Instalar app
driver.installApp("/path/to/app.apk");

# Verificar se app está instalado
boolean installed = driver.isAppInstalled("com.example.app");

# Desinstalar app
driver.removeApp("com.example.app");

# Fechar app (sem desinstalar)
driver.closeApp();

# Reabrir app
driver.launchApp();

6. Orientação e Viewport

# WEB: Redimensionar janela
driver.manage().window().setSize(new Dimension(375, 667));

# MOBILE: Rotacionar dispositivo
driver.rotate(ScreenOrientation.LANDSCAPE);
driver.rotate(ScreenOrientation.PORTRAIT);

# Obter orientação atual
ScreenOrientation orientation = driver.getOrientation();

7. Notificações e Permissões

Web: Não gerencia notificações ou permissões do sistema.

Mobile: Pode interagir com:

  • Notificações push
  • Permissões do sistema (câmera, localização, etc.)
  • Alertas nativos
  • Teclado virtual

Resumo das Principais Diferenças

Aspecto Web Mobile
Seletores CSS, XPath completos Resource ID, Accessibility ID
Interações Click, Type Tap, Swipe, Pinch, Long Press
Contextos Único (página) Múltiplos (Native, WebView)
Apps Não aplicável Instalar, Desinstalar, Gerenciar
Orientacao Redimensionar janela Rotacionar dispositivo

Troubleshooting - Problemas Comuns

"UIAutomator2 not installed"

Problema: Driver UiAutomator2 não encontrado.

Solução:

appium driver install uiautomator2
appium driver list  # Verificar instalação

"Device not found"

Problema: Appium não encontra dispositivo.

Solução:

adb devices  # Verificar dispositivos
adb kill-server
adb start-server
adb devices  # Tentar novamente

"App not installed"

Problema: App não instala no dispositivo.

Solução:

adb install app.apk
adb uninstall com.example.app  # Se já instalado
adb install -r app.apk  # Reinstalar

"Session not created"

Problema: Não consegue criar sessão Appium.

Verificações:

  • Appium Server está rodando? (appium)
  • Capabilities estão corretas?
  • Versão do Android compatível?
  • APK existe no caminho especificado?
  • Package e Activity estão corretos?

"Element not found"

Problema: Não encontra elementos na tela.

Solução:

  • Use Appium Inspector para inspecionar elementos
  • Verifique se está no contexto correto (Native vs WebView)
  • Adicione esperas explícitas
  • Verifique se o elemento está visível na tela

"Connection refused"

Problema: Não consegue conectar ao Appium Server.

Solução:

# Verificar se Appium está rodando
lsof -i :4723  # macOS/Linux
netstat -ano | findstr :4723  # Windows

# Reiniciar Appium
appium

Passo 2: Instalar Xcode

Baixe Xcode da App Store (gratuito, mas grande ~12GB).

Verificar: xcodebuild -version

Passo 3: Command Line Tools

Instale ferramentas de linha de comando do Xcode.

xcode-select --install

Passo 4: Instalar Appium

Framework de automação mobile multiplataforma.

npm install -g appium

# 1. Iniciar Appium Server
appium

xcrun simctl list devices

open -a Simulator

# (depende da linguagem escolhida)

Dica para Iniciantes

Siga os passos na ordem: Instalação → Preparar Projeto → Capabilities → Exemplos. iOS tem requisitos mais específicos que Android, então preste atenção aos detalhes de instalação.

Guia Completo de Instalação iOS

Aviso Importante

Automação iOS só funciona em macOS. Se você está em Windows ou Linux, considere usar serviços em nuvem como BrowserStack, Sauce Labs ou AWS Device Farm.

1. Instalar Node.js e npm

# macOS: Usar Homebrew (recomendado)
brew install node

# Ou baixar instalador em nodejs.org

# Verificar instalação
node --version  # Deve mostrar v18.x ou superior
npm --version   # Deve mostrar 9.x ou superior

2. Instalar Xcode

Passo a passo:

  1. Abra a App Store no Mac
  2. Procure por "Xcode"
  3. Clique em "Obter" ou "Instalar" (gratuito, mas ~12GB)
  4. Aguarde o download e instalação (pode levar horas)
  5. Após instalação, abra Xcode uma vez para aceitar os termos
  6. Xcode → Settings → Locations → Command Line Tools: Selecione a versão instalada

3. Instalar Command Line Tools

# Instalar Command Line Tools
xcode-select --install

# Se já instalado, pode aparecer erro - isso é normal

# Verificar instalação
xcode-select -p  # Deve mostrar: /Library/Developer/CommandLineTools
xcodebuild -version  # Deve mostrar versão do Xcode

4. Baixar Simuladores iOS

  1. Abra Xcode
  2. Xcode → Settings (ou Preferences em versões antigas)
  3. Abra a aba "Platforms" ou "Components"
  4. Baixe pelo menos um simulador iOS (recomendado: iOS 15 ou 16)
  5. Aguarde o download (pode levar tempo)
# Listar simuladores disponíveis
xcrun simctl list devices

# Iniciar simulador específico
xcrun simctl boot "iPhone 13"

# Abrir Simulator app
open -a Simulator

# Desligar simulador
xcrun simctl shutdown all

5. Instalar Appium e Drivers

# Instalar Appium globalmente
npm install -g appium

# Instalar driver XCUITest para iOS
appium driver install xcuitest

# Verificar instalação
appium --version
appium driver list

# Instalar Appium Doctor (opcional, mas recomendado)
appium driver doctor xcuitest

6. Configurar Certificados (Para Dispositivos Físicos)

Nota: Para testar em dispositivos físicos iOS, você precisa:

  1. Conta de desenvolvedor Apple (gratuita ou paga)
  2. Configurar certificados no Xcode
  3. Conectar dispositivo via USB
  4. Confiar no computador no dispositivo

Para iniciantes, recomendamos começar com simuladores, que não requerem certificados.

Próximos Passos

Após preparar o projeto, você está pronto para configurar as Capabilities e escrever seus primeiros testes. Veja a seção "Capabilities" para entender como configurar a conexão com simuladores ou dispositivos iOS.

Capabilities iOS - Guia Completo

Capabilities são configurações que informam ao Appium como se conectar e interagir com seu dispositivo ou simulador iOS. Pense nelas como "instruções" para o Appium.

Capabilities Obrigatórias

platformName: "iOS"

Obrigatório. Define a plataforma. Sempre "iOS" para dispositivos iOS.

automationName: "XCUITest"

Obrigatório. Driver de automação. XCUITest é o padrão moderno para iOS.

Capabilities Importantes

platformVersion: "15.0"

Versão do iOS. Descubra com: xcrun simctl list devices ou no dispositivo físico: Settings → General → About

deviceName: "iPhone 13"

Nome do dispositivo ou simulador. Listar: xcrun simctl list devices

udid: "A1B2C3D4-E5F6-..."

ID único do dispositivo. Obtido com xcrun simctl list devices ou instruments -s devices. Necessário quando há múltiplos dispositivos.

Capabilities para Aplicativos

app: "/path/to/app.app"

Caminho completo para o arquivo .app (simulador) ou .ipa (dispositivo físico). Use caminho absoluto.

bundleId: "com.example.app"

Bundle ID da aplicação. Descubra com: plutil -p app.app/Info.plist | grep CFBundleIdentifier

Capabilities de Comportamento

noReset: false

Se true, não limpa dados do app entre testes. Útil para testes que dependem de estado anterior.

fullReset: false

Se true, desinstala e reinstala o app completamente. Use apenas quando necessário.

wdaLaunchTimeout: 60000

Timeout em milissegundos para WebDriverAgent iniciar. Aumente se WebDriverAgent demorar para compilar.

useNewWDA: false

Se true, reconstrói WebDriverAgent a cada sessão. Use apenas se houver problemas de conexão.

Dicas Importantes

  • Para simuladores, use arquivo .app. Para dispositivos físicos, use .ipa
  • Bundle ID é essencial - verifique sempre antes de executar testes
  • WebDriverAgent pode demorar na primeira execução (compilação)
  • Para testes em navegador, use browserName: "Safari" em vez de app
  • Simuladores são mais rápidos para desenvolvimento; dispositivos físicos para validação final

import io.appium.java_client.ios.options.XCUITestOptions;
import org.openqa.selenium.By;
import org.openqa.selenium.support.ui.WebDriverWait;
import org.openqa.selenium.support.ui.ExpectedConditions;
import java.net.URL;
import java.time.Duration;

public class IOSTest {
    private static IOSDriver driver;
    
    public static void main(String[] args) {
        // Configurar capabilities
        XCUITestOptions options = new XCUITestOptions();
        options.setPlatformName("iOS");
        options.setPlatformVersion("15.0");
        options.setDeviceName("iPhone 13");
        options.setAutomationName("XCUITest");
        options.setApp("/caminho/completo/app.app");
        options.setBundleId("com.example.app");
        options.setNoReset(false);
        options.setWdaLaunchTimeout(Duration.ofSeconds(60));
        
        // Inicializar driver
        driver = new IOSDriver(
            new URL("http://localhost:4723"), 
            options
        );
        
        // Exemplo: Encontrar elemento por Accessibility ID
        WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
        wait.until(ExpectedConditions.presenceOfElementLocated(
            By.id("loginButton")
        )).click();
        
        // Exemplo: Preencher campo de texto
        driver.findElement(By.id("username")).sendKeys("usuario@exemplo.com");
        
        // Exemplo: Swipe
        // (veja seção de gestos para exemplos completos)
        
        // Fechar driver
        driver.quit();
    }
}
from appium import webdriver
from appium.options.ios import XCUITestOptions
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# Configurar capabilities
options = XCUITestOptions()
options.platform_name = "iOS"
options.platform_version = "15.0"
options.device_name = "iPhone 13"
options.automation_name = "XCUITest"
options.app = "/caminho/completo/app.app"
options.bundle_id = "com.example.app"
options.no_reset = False
options.wda_launch_timeout = 60000

# Inicializar driver

try:

    wait = WebDriverWait(driver, 10)

        By.ID, "loginButton"

finally:

Boas Práticas nos Exemplos

Sempre use esperas explícitas

Elementos mobile podem demorar para aparecer. Use WebDriverWait em vez de Thread.sleep().

Prefira Accessibility ID

Accessibility ID é mais estável que XPath em iOS. Use sempre que possível.

Sempre feche o driver

Use try/finally ou ensure para garantir que o driver seja fechado mesmo em caso de erro.

Trate exceções

Mobile pode ter mais falhas que web. Trate exceções adequadamente e adicione logs.

Diferenças: Automação Web vs Mobile iOS

Automação mobile iOS tem diferenças fundamentais em relação à automação web. Entender essas diferenças é crucial para o sucesso.

1. Seletores e Localização de Elementos

Web (Selenium)

  • ID, Class, Name
  • XPath, CSS Selectors
  • Link Text, Partial Link
  • Tag Name

Mobile iOS (Appium)

  • Accessibility ID (recomendado)
  • Name
  • Class Name
  • XPath (limitado, mais lento)
  • iOS Predicate String
  • iOS Class Chain

2. Interações e Gestos iOS

# WEB: Cliques simples
driver.findElement(By.id("button")).click()

# MOBILE iOS (Appium 2 + XCUITest): gestos prontos do driver
# Tap (toque simples)
driver.executeScript("mobile: tap", Map.of("x", 200, "y", 400));

# Swipe (deslizar)
driver.executeScript("mobile: swipe", Map.of("direction", "up"));

# Long Press (toque longo)
driver.executeScript("mobile: touchAndHold", Map.of(
    "elementId", ((RemoteWebElement) element).getId(), "duration", 1.0));

# Pinch/Zoom (pinçar): scale maior que 1 aproxima
driver.executeScript("mobile: pinch", Map.of(
    "elementId", ((RemoteWebElement) element).getId(), "scale", 2.0, "velocity", 1.0));

# Scroll específico iOS
JavascriptExecutor js = (JavascriptExecutor) driver;
HashMap<String, String> scrollObject = new HashMap<>();
scrollObject.put("direction", "down");
js.executeScript("mobile: scroll", scrollObject);

3. Contextos e WebViews iOS

Web: Sempre trabalha em um único contexto (a página web).

Mobile iOS: Pode ter múltiplos contextos:

  • NATIVE_APP: Contexto nativo da aplicação iOS
  • WEBVIEW: Contexto web dentro do app (WKWebView)
# Listar contextos disponíveis
Set<String> contexts = driver.getContextHandles();

# Alternar para WebView
driver.context("WEBVIEW_1");  # iOS usa números

# Voltar para Native
driver.context("NATIVE_APP");

4. Esperas e Sincronização iOS

Web

  • WebDriverWait
  • ExpectedConditions
  • Implicit Wait
  • Page Load Timeout

Mobile iOS

  • WebDriverWait (similar)
  • Espera por Elemento
  • Espera por Alertas
  • Timeout de instalação
  • wdaLaunchTimeout

5. Instalação e Gerenciamento de Apps iOS

# WEB: Não aplicável

# MOBILE iOS: Instalar app
driver.installApp("/path/to/app.app");  # Simulador
# ou
driver.installApp("/path/to/app.ipa");  # Dispositivo físico

# Verificar se app está instalado
boolean installed = driver.isAppInstalled("com.example.app");

# Desinstalar app
driver.removeApp("com.example.app");

# Fechar app (sem desinstalar)
driver.closeApp();

# Reabrir app
driver.launchApp();

# Ativar app em background
driver.activateApp("com.example.app");

6. Orientação e Viewport iOS

# WEB: Redimensionar janela
driver.manage().window().setSize(new Dimension(375, 667));

# MOBILE iOS: Rotacionar dispositivo
driver.rotate(ScreenOrientation.LANDSCAPE);
driver.rotate(ScreenOrientation.PORTRAIT);

# Obter orientação atual
ScreenOrientation orientation = driver.getOrientation();

# iOS específico: Lock/Unlock orientação
driver.lockDevice();  # Bloquear tela
driver.unlockDevice();  # Desbloquear

7. Alertas e Permissões iOS

Web: Não gerencia alertas nativos ou permissões do sistema.

Mobile iOS: Pode interagir com:

  • Alertas nativos (UIAlertController)
  • Permissões do sistema (câmera, localização, notificações)
  • Action Sheets
  • Teclado virtual
  • Date/Time Pickers
# Aceitar alerta
driver.switchTo().alert().accept();

# Cancelar alerta
driver.switchTo().alert().dismiss();

# Obter texto do alerta
String alertText = driver.switchTo().alert().getText();

Resumo das Principais Diferenças iOS

Aspecto Web Mobile iOS
Seletores CSS, XPath completos Accessibility ID, Predicate
Interações Click, Type Tap, Swipe, Pinch, Long Press
Contextos Único (página) Múltiplos (Native, WebView)
Apps Não aplicável .app (simulador) ou .ipa (físico)
Requisitos Qualquer OS macOS obrigatório

Troubleshooting - Problemas Comuns iOS

"XCUITest not installed"

Problema: Driver XCUITest não encontrado.

Solução:

appium driver install xcuitest
appium driver list  # Verificar instalação

"Simulator not found"

Problema: Appium não encontra simulador.

Solução:

xcrun simctl list devices  # Verificar simuladores
open -a Simulator  # Abrir Simulator
xcrun simctl boot "iPhone 13"  # Iniciar simulador específico

"WebDriverAgent build failed"

Problema: WebDriverAgent não compila.

Soluções:

  • Verifique se Xcode Command Line Tools estão instalados
  • Execute: xcode-select --install
  • Certifique-se que Xcode está atualizado
  • Tente aumentar wdaLaunchTimeout nas capabilities

"Code signing required"

Problema: Erro de assinatura de código (dispositivos físicos).

Solução:

  1. Abra Xcode
  2. Xcode → Settings → Accounts
  3. Adicione sua Apple ID
  4. Selecione sua equipe de desenvolvimento
  5. Para simuladores, não é necessário

"Session not created"

Problema: Não consegue criar sessão Appium.

Verificações:

  • Appium Server está rodando? (appium)
  • Capabilities estão corretas?
  • Versão do iOS compatível?
  • App existe no caminho especificado?
  • Bundle ID está correto?
  • Simulador está iniciado?

"Element not found"

Problema: Não encontra elementos na tela.

Solução:

  • Use Appium Inspector para inspecionar elementos
  • Verifique se está no contexto correto (Native vs WebView)
  • Use Accessibility ID em vez de XPath quando possível
  • Adicione esperas explícitas
  • Verifique se o elemento está visível na tela

"Connection refused"

Problema: Não consegue conectar ao Appium Server.

Solução:

# Verificar se Appium está rodando
lsof -i :4723

# Reiniciar Appium
appium

"WebDriverAgent timeout"

Problema: WebDriverAgent demora muito para iniciar.

Solução:

  • Aumente wdaLaunchTimeout para 120000 (2 minutos)
  • Use useNewWDA: false para reutilizar WebDriverAgent
  • Primeira execução sempre demora mais (compilação)
