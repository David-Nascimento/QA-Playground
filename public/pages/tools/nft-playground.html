NFT Playground - Simulador de Testes Não Funcionais

Ambiente educacional 100% client-side para simulação de Testes Não Funcionais (NFT). Este playground permite avaliar performance percebida, resiliência e comportamento do front-end sem aplicar carga real a servidores externos.

Importante: Ambiente Educacional

Todos os cenários são simulados localmente no navegador. Nenhum teste de carga real é executado e nenhuma chamada agressiva é feita a servidores externos. Este ambiente é destinado exclusivamente para fins educacionais e de aprendizado.

Antes de começar: o que cada teste responde

Testes não funcionais diferem pelo formato da carga ao longo do tempo. Cada gráfico mostra usuários simultâneos (vertical) ao longo do teste (horizontal).

Carga (load)

Volume esperado no dia a dia, com rampa e platô. Responde: "o sistema aguenta o uso normal dentro do SLO?"

Estresse (stress)

Aumenta a carga em degraus além do esperado até quebrar. Responde: "onde está o limite e como o sistema falha?"

Pico (spike)

Salto repentino, como uma campanha ou a abertura de vendas. Responde: "o sistema escala a tempo e se recupera depois?"

Resistência (soak)

Carga moderada por horas. Responde: "há vazamento de memória, conexões ou disco com o tempo?"

Métricas que importam

Latência p95 / p99
95% (ou 99%) das respostas foram mais rápidas que este valor. É o que os SLOs usam, porque a média esconde os usuários mais lentos.
Vazão (throughput)
Requisições atendidas por segundo. Se a carga sobe e a vazão para de subir, você achou um gargalo.
Taxa de erro
Fração de respostas com falha (5xx, timeouts). Sob carga, ela costuma subir antes da latência explodir.
Apdex
Nota de 0 a 1 da satisfação: respostas até T são "satisfeitas", até 4T "toleradas" e acima disso "frustradas".

Pratique com ferramentas de verdade

O simulador acima ensina os conceitos. No dia a dia, esses testes são escritos como código e rodam no pipeline. Os exemplos abaixo usam a API mock do próprio QA Playground, que você sobe localmente com npm run dev:api.

Use com responsabilidade: rode testes de carga só contra a API local ou um ambiente seu. Nunca aponte k6, JMeter ou Gatling para o site publicado ou para serviços de terceiros.

Rode com k6 run carga.js. Os thresholds fazem o comando terminar com erro se o p95 passar de 300 ms: é isso que reprova o pipeline.

import http from 'k6/http';
import { check, sleep } from 'k6';

// Teste de carga: rampa até 10 usuários virtuais, platô e desaceleração
export const options = {
  stages: [
    { duration: '30s', target: 10 },
    { duration: '1m', target: 10 },
    { duration: '15s', target: 0 },
  ],
  thresholds: {
    http_req_duration: ['p(95)<300', 'p(99)<800'], // percentis, não média
    http_req_failed: ['rate<0.01'],                // menos de 1% de erros
  },
};

const BASE = __ENV.BASE_URL || 'http://localhost:3001/api';

export default function () {
  const res = http.get(`${BASE}/health`);
  check(res, { 'status 200': (r) => r.status === 200 });
  sleep(1); // "tempo de pensar" do usuário
}

Os cenários error-503 e timeout estão documentados em GET /api/docs. O cenário é aplicado antes da autenticação, então /api/users responde sem token.

import http from 'k6/http';
import { check } from 'k6';

// Resiliência: a API mock do QA Playground força falhas com ?scenario=
export const options = { vus: 5, iterations: 50 };
const BASE = __ENV.BASE_URL || 'http://localhost:3001/api';

export default function () {
  // 503 simulado: o cliente deve tratar como "tente mais tarde"
  const unavailable = http.get(`${BASE}/users?scenario=error-503`);
  check(unavailable, { 'responde 503': (r) => r.status === 503 });

  // Timeout: a API demora 10 s; o cliente desiste em 2 s
  const slow = http.get(`${BASE}/users?scenario=timeout`, { timeout: '2s' });
  check(slow, { 'cliente aplicou timeout': (r) => r.error_code !== 0 });
}

Performance percebida também se testa no front-end: tempo de resposta da interface e métricas do navegador.

import { test, expect } from '@playwright/test';

test('LCP da home abaixo de 2,5 s', async ({ page }) => {
  await page.goto('/');
  const lcp = await page.evaluate(
    () =>
      new Promise<number>((resolve) => {
        new PerformanceObserver((list) => {
          const entries = list.getEntries();
          resolve(entries[entries.length - 1].startTime);
        }).observe({ type: 'largest-contentful-paint', buffered: true });
      })
  );
  expect(lcp).toBeLessThan(2500);
});

test('interface responde em até 200 ms sob 1000 linhas', async ({ page }) => {
  await page.goto('/pages/tools/nft/load-large-table.html');
  await page.getByRole('button', { name: 'Gerar Tabela' }).click();

  const inicio = Date.now();
  await page.getByRole('button', { name: 'Limpar' }).click();
  await expect(page.locator('table tbody tr')).toHaveCount(0);
  expect(Date.now() - inicio).toBeLessThan(200);
});

Informações sobre Limites e Proteções
  • Limite de testes por sessão: 10 execuções
  • Cooldown entre testes: 3 segundos
  • Limite máximo de elementos: 1000 itens
  • Limite máximo de latência simulada: 5 segundos
  • Limite de ações simultâneas: 1 teste por vez

Estes limites existem para proteger infraestrutura e garantir uso responsável deste ambiente educacional.
