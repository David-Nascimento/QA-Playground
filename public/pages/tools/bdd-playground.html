Como Usar e Boas Práticas de BDD

O que é BDD?

Behavior-Driven Development (BDD) é uma metodologia que foca no comportamento observável do software, usando uma linguagem natural estruturada (Gherkin) para descrever cenários de teste de forma compreensível para todos os stakeholders.

Estrutura Básica do Gherkin

  • Feature: Descreve a funcionalidade sendo testada
  • Como [persona]: Define quem se beneficia da funcionalidade
  • Eu quero [objetivo]: O que a persona deseja fazer
  • Para [benefício]: O valor ou benefício esperado
  • Scenario: Um exemplo específico de comportamento
  • Given: Contexto inicial (pré-condições)
  • When: Ação que dispara o comportamento
  • Then: Resultado esperado (pós-condições)
  • And/But: Conectores para adicionar mais passos

Boas Práticas

  • Use linguagem de negócio: Escreva em termos que stakeholders entendam
  • Seja específico: Evite ambiguidades, use dados concretos
  • Um cenário = um comportamento: Não misture múltiplos comportamentos
  • Given-When-Then claro: Contexto → Ação → Resultado esperado
  • Nomes descritivos: Scenario deve explicar o que está sendo testado
  • Evite detalhes técnicos: Foque no "o quê", não no "como"
  • Use Background: Para pré-condições compartilhadas entre cenários
  • Scenario Outline: Para testar múltiplos dados com mesmo comportamento

Evite

  • Passos muito longos ou complexos
  • Linguagem técnica desnecessária (ex: "clique no botão submit")
  • Cenários que testam múltiplas funcionalidades
  • Dados hardcoded quando Scenario Outline seria melhor
  • Passos que dependem de ordem específica sem contexto claro

Dica de Uso
