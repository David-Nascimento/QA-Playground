Módulo 3: Níveis e Tipos de Teste

Entenda os diferentes níveis de teste (componente, integração, sistema, aceitação) e os tipos de teste (funcional, não-funcional, estrutural, baseado em experiência) conforme definidos pelo ISTQB.

Níveis de Teste (ISTQB)

Os níveis de teste organizam os testes de acordo com o escopo e o objetivo. Cada nível tem um propósito específico e testa diferentes aspectos do software em diferentes momentos do desenvolvimento.

Teste de Componente (Unit Testing)

Definição

Testa componentes individuais ou módulos do software de forma isolada. Geralmente feito por desenvolvedores, testa unidades menores de código como funções, métodos ou classes.

Características

  • Testa unidades isoladas de código
  • Rápido de executar
  • Fácil de automatizar
  • Geralmente feito por desenvolvedores
  • Foca em lógica de negócio e cálculos

Exemplo

Testar uma função que calcula desconto, verificando se retorna o valor correto para diferentes entradas:

  • Desconto de 10% em um produto de R$ 100,00 deve retornar R$ 90,00
  • Desconto de 0% deve retornar o valor original
  • Valor negativo deve retornar erro ou tratar adequadamente

Teste de Integração

Definição

Testa a interação entre componentes ou sistemas. Verifica se as interfaces funcionam corretamente quando os componentes trabalham juntos.

Características

  • Testa múltiplos componentes trabalhando juntos
  • Verifica interfaces e comunicação entre componentes
  • Pode testar integração com sistemas externos (APIs, bancos de dados)
  • Pode ser feito por desenvolvedores ou QAs
  • Mais lento que testes de unidade

Exemplo

Testar se o módulo de autenticação se comunica corretamente com o módulo de perfil do usuário:

  • Quando o usuário faz login, o perfil é carregado corretamente
  • Quando o perfil é atualizado, a sessão reflete as mudanças
  • Quando há erro na autenticação, o perfil não é carregado

Teste de Sistema

Definição

Testa o sistema completo e integrado. Verifica se atende aos requisitos funcionais e não-funcionais em um ambiente que simula a produção.

Características

  • Testa o sistema completo end-to-end
  • Verifica requisitos funcionais e não-funcionais
  • Executado em ambiente similar à produção
  • Geralmente feito por QAs
  • Inclui testes de regressão

Exemplo

Testar todo o fluxo de compra em um e-commerce, desde a seleção do produto até o pagamento:

  • Adicionar produto ao carrinho
  • Preencher dados de entrega
  • Selecionar método de pagamento
  • Processar pagamento
  • Confirmar pedido
  • Enviar email de confirmação

Teste de Aceitação

Definição

Testa se o sistema atende aos critérios de aceitação do usuário. Pode ser UAT (User Acceptance Testing) ou AT (Acceptance Testing). Valida se o software está pronto para ser usado pelos usuários finais.

Características

  • Foca em requisitos de negócio e necessidades do usuário
  • Geralmente feito por usuários finais ou product owners
  • Pode ser feito em ambiente de produção ou staging
  • Valida se o software resolve o problema do usuário
  • Última etapa antes do lançamento

Tipos de Teste de Aceitação

  • UAT (User Acceptance Testing): Usuários finais testam o sistema
  • AT (Acceptance Testing): Validação contra critérios de aceitação definidos
  • Alpha Testing: Testes internos antes do lançamento
  • Beta Testing: Testes com usuários externos em ambiente controlado

Exemplo

Usuários finais testam o sistema em ambiente de produção para validar se atende suas necessidades:

  • O sistema permite realizar tarefas que eles precisam fazer?
  • A interface é intuitiva e fácil de usar?
  • O sistema atende aos requisitos de negócio definidos?
  • O desempenho é aceitável para o uso real?

Tipos de Teste

Os tipos de teste categorizam os testes de acordo com o que está sendo testado e como está sendo testado. Um teste pode ser classificado por múltiplos tipos simultaneamente.

Testes Funcionais

Definição

Avaliam se o software faz o que deveria fazer, testando funcionalidades e requisitos. Focam no comportamento do sistema e nas funcionalidades implementadas.

O que é Testado

  • Funcionalidades do sistema
  • Requisitos de negócio
  • Regras de negócio
  • Fluxos de usuário
  • Integrações entre módulos
  • Validações e regras de entrada

Exemplo

Testar se o botão "Adicionar ao carrinho" realmente adiciona o produto ao carrinho:

  • Quando clicado, o produto aparece no carrinho
  • O preço é calculado corretamente
  • Múltiplos produtos podem ser adicionados
  • O carrinho persiste entre páginas

Testes Não-Funcionais

Definição

Avaliam características como performance, usabilidade, segurança, confiabilidade. Focam em "quão bem" o sistema faz, não em "o que" o sistema faz.

O que é Testado

  • Performance e tempo de resposta
  • Usabilidade e experiência do usuário
  • Segurança e vulnerabilidades
  • Confiabilidade e estabilidade
  • Compatibilidade entre navegadores e dispositivos
  • Escalabilidade e capacidade

Exemplo

Testar se a página carrega em menos de 3 segundos, ou se o sistema suporta 1000 usuários simultâneos:

  • Tempo de carregamento da página inicial
  • Tempo de resposta de requisições de API
  • Comportamento sob carga pesada
  • Uso de recursos (CPU, memória)

Testes Estruturais (Caixa Branca)

Definição

Baseados na estrutura interna do código. Testam caminhos de execução, condições, loops. Requerem conhecimento do código interno do sistema.

O que é Testado

  • Cobertura de código (statements, branches, conditions)
  • Caminhos de execução
  • Lógica de condições e loops
  • Fluxo de dados

Exemplo

Garantir que todas as branches de um if/else sejam testadas, ou que todos os loops sejam executados:

  • Testar tanto o caminho true quanto false de condições
  • Testar loops executando 0, 1 e múltiplas iterações
  • Garantir que todas as linhas de código sejam executadas

Testes Baseados em Experiência

Definição

Baseados no conhecimento e experiência do testador. Incluem testes exploratórios e ad-hoc, onde o testador usa sua intuição e conhecimento para encontrar bugs.

O que é Testado

  • Cenários não documentados
  • Casos de borda identificados pela experiência
  • Áreas de risco conhecidas
  • Comportamentos inesperados

Exemplo

Explorar o sistema livremente, tentando quebrá-lo de formas criativas baseadas em experiência anterior:

  • Tentar inputs inesperados baseado em bugs anteriores
  • Testar cenários que geralmente têm problemas
  • Explorar funcionalidades sem seguir scripts
  • Usar conhecimento de domínio para encontrar problemas
