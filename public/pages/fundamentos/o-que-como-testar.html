Módulo 7: O Que Testar e Como Testar

Aprenda a planejar e executar testes de forma sistemática, criando casos de teste eficazes e cobrindo diferentes aspectos do software de forma organizada e profissional.

O Que Testar

Compreender o que testar é fundamental para garantir uma cobertura adequada do software. Diferentes aspectos do sistema precisam de diferentes tipos de testes.

Funcionalidade

Testes Funcionais

Focam em verificar se o software faz o que deveria fazer conforme os requisitos:

  • Validação de regras de negócio: Verificar se as regras implementadas funcionam corretamente
  • Fluxos de usuário completos: Testar jornadas completas do usuário do início ao fim
  • Integração entre módulos: Verificar se diferentes partes do sistema trabalham juntas corretamente
  • APIs e endpoints: Testar interfaces de comunicação e integração
  • Validações de formulários: Verificar se campos são validados adequadamente
  • Regras de entrada e saída: Validar se dados são processados e retornados corretamente

Interface e Usabilidade

Testes de UI/UX

Verificam aspectos visuais e de experiência do usuário:

  • Layout e responsividade: Verificar se a interface se adapta a diferentes tamanhos de tela
  • Acessibilidade (WCAG): Garantir que o sistema seja acessível a todos os usuários
  • Navegação e usabilidade: Verificar se é fácil navegar e usar o sistema
  • Compatibilidade entre navegadores: Testar se funciona em diferentes navegadores
  • Design system e consistência visual: Verificar se elementos seguem padrões visuais consistentes
  • Feedback visual: Verificar se mensagens e indicações são claras

Performance

Testes de Performance

Avaliam a velocidade e eficiência do sistema:

  • Tempo de resposta: Verificar se o sistema responde dentro de tempos aceitáveis
  • Capacidade e carga: Testar se o sistema suporta a carga esperada
  • Stress e volume: Testar comportamento sob condições extremas
  • Escalabilidade: Verificar se o sistema pode crescer conforme necessário
  • Uso de recursos: Verificar consumo de CPU, memória, rede, disco

Segurança

Testes de Segurança

Verificam proteção contra vulnerabilidades e ameaças:

  • Autenticação e autorização: Verificar se apenas usuários autorizados acessam recursos
  • Injeção SQL e XSS: Testar proteção contra ataques comuns
  • Dados sensíveis: Verificar se informações sensíveis estão protegidas
  • HTTPS e criptografia: Verificar se comunicações são seguras
  • Vulnerabilidades conhecidas (OWASP Top 10): Testar contra ameaças comuns

Qualidade de Código

Testes de Código

Avaliam a qualidade do código fonte:

  • Cobertura de código: Verificar quantas linhas/funcionalidades estão cobertas por testes
  • Análise estática: Identificar problemas no código sem executá-lo
  • Code smells: Identificar padrões de código que podem indicar problemas
  • Padrões e convenções: Verificar se o código segue padrões estabelecidos

Como Testar: Planejamento

1. Entenda os Requisitos

Antes de começar a testar, é essencial entender completamente o que está sendo testado:

  • Leia todos os requisitos e especificações relacionadas
  • Identifique ambiguidades e esclareça dúvidas com o time
  • Entenda o contexto de negócio e os objetivos da funcionalidade
  • Identifique stakeholders e entenda suas expectativas
  • Revisite requisitos durante o teste para garantir alinhamento

2. Crie Casos de Teste

Documente casos de teste cobrindo diferentes cenários:

Cenários Positivos (Happy Path)

Testam o comportamento esperado quando tudo funciona corretamente. São os casos mais básicos e importantes.

Exemplo: Usuário faz login com credenciais válidas e é redirecionado para o dashboard.

Cenários Negativos (Validações e Erros)

Testam o comportamento quando há erros ou dados inválidos. Verificam se o sistema trata erros adequadamente.

Exemplo: Usuário tenta fazer login com senha incorreta e recebe mensagem de erro apropriada.

Casos de Borda (Edge Cases)

Testam valores nos limites ou situações extremas que podem causar problemas.

Exemplo: Campo aceita máximo de 100 caracteres - testar com 99, 100 e 101 caracteres.

Casos Extremos (Boundary Values)

Similar aos casos de borda, mas focam especificamente nos valores limite.

Exemplo: Campo numérico aceita valores de 1 a 100 - testar com 0, 1, 100, 101.

Como Testar: Execução

3. Execute Testes Sistematicamente

Siga seus casos de teste, mas também esteja aberto a testes exploratórios:

  • Execute casos de teste em ordem lógica
  • Documente resultados de cada teste
  • Compare resultados esperados com resultados reais
  • Esteja aberto a descobrir bugs não previstos nos casos de teste
  • Use testes exploratórios para complementar testes scriptados

Dica: Às vezes, os melhores bugs são encontrados quando você se desvia do script e explora o sistema livremente.

4. Documente Evidências

Capture evidências que comprovem o comportamento observado. Isso é essencial para reportar bugs e para documentação:

  • Screenshots: Capture imagens do comportamento observado
  • Logs: Salve logs do servidor ou aplicação
  • Vídeos: Grave vídeos mostrando o comportamento (útil para bugs intermitentes)
  • Dados de teste: Documente quais dados foram usados
  • Passos executados: Anote exatamente o que foi feito

Ferramentas úteis: Lightshot, ShareX, Snipping Tool, gravadores de tela, ferramentas de captura do navegador.

Estrutura de um Caso de Teste

Elementos Essenciais

Um caso de teste bem documentado deve conter:

Identificação

  • ID único do caso de teste
  • Título descritivo e claro
  • Categoria ou tipo de teste

Descrição

  • Objetivo do teste
  • Pré-condições necessárias
  • Dados de teste utilizados

Passos de Execução

  • Lista numerada e sequencial de ações
  • Passos claros e acionáveis
  • Específicos o suficiente para serem reproduzidos

Resultados Esperados

  • O que deve acontecer após executar os passos
  • Critérios de aceitação claros

Resultados Reais

  • O que realmente aconteceu
  • Status do teste (Passou/Falhou)
  • Observações adicionais

Priorização de Testes

Como Priorizar

Nem todos os testes têm a mesma importância. Priorize baseado em:

Criticidade da Funcionalidade

Teste primeiro funcionalidades críticas para o negócio ou que têm maior impacto se falharem.

Risco

Funcionalidades com maior risco de ter bugs devem ser testadas primeiro.

Frequência de Uso

Funcionalidades usadas frequentemente pelos usuários devem ter prioridade.

Complexidade

Funcionalidades complexas geralmente têm maior chance de bugs.
