Módulo 1: Introdução e Conceitos Básicos

Aprenda o que é teste de software, por que testamos, e os conceitos fundamentais que todo QA precisa conhecer desde o início de sua jornada.

O que é Teste de Software?

Definição (ISTQB)

Segundo o ISTQB (International Software Testing Qualifications Board), teste de software é o processo que consiste em atividades de ciclo de vida do desenvolvimento, tanto estáticas quanto dinâmicas, preocupadas com o planejamento, preparação e avaliação de software e produtos de trabalho relacionados para determinar se eles satisfazem os requisitos especificados, para demonstrar que são adequados para o propósito e para detectar defeitos.

Definição Simplificada

Teste de software é o processo de verificar se um sistema funciona corretamente, se atende aos requisitos especificados, e se não possui defeitos que possam impactar usuários ou o negócio.

Em outras palavras, testar é a atividade que garante que o software funciona como esperado antes de ser entregue aos usuários finais.

Por Que Testamos?

Testamos software por diversas razões importantes:

  • Encontrar defeitos: Identificar bugs e problemas antes que cheguem aos usuários
  • Garantir qualidade: Assegurar que o software atende aos requisitos e expectativas
  • Reduzir riscos: Minimizar a chance de falhas em produção que possam causar prejuízos
  • Fornecer confiança: Dar segurança à equipe e stakeholders de que o software está funcionando
  • Melhorar a experiência do usuário: Garantir que os usuários tenham uma experiência positiva
  • Cumprir requisitos legais e regulatórios: Em alguns setores, testes são obrigatórios

Conceitos Fundamentais

Bug, Defeito, Falha e Erro

É importante entender a diferença entre esses termos, que são frequentemente usados como sinônimos, mas têm significados distintos:

Erro (Error)

Um erro é uma ação humana que produz um resultado incorreto. É o ato de cometer um engano, geralmente durante o desenvolvimento do software.

Exemplo: Um desenvolvedor escreve um código que calcula o desconto incorretamente porque usou a fórmula errada.

Defeito (Defect)

Um defeito é uma imperfeição ou falha no código que pode causar um comportamento incorreto. O defeito existe no código, mas pode não ter sido descoberto ainda.

Exemplo: O código contém um erro lógico onde a divisão por zero não é tratada.

Falha (Failure)

Uma falha ocorre quando o software se comporta de forma diferente do esperado em execução. A falha é a manifestação visível de um defeito.

Exemplo: Quando o usuário tenta calcular um desconto, o sistema exibe uma mensagem de erro ou trava.

Bug

Bug é um termo informal e amplamente usado para se referir a qualquer defeito, falha ou problema no software. Na prática, "bug" é frequentemente usado como sinônimo de "defeito" ou "falha".

Teste vs. Depuração (Debugging)

Teste: Processo de encontrar defeitos e falhas no software.

Depuração: Processo de encontrar, analisar e corrigir a causa raiz de uma falha.

Enquanto o teste identifica que algo está errado, a depuração descobre o porquê e corrige o problema. Geralmente, o teste é feito por QAs e a depuração por desenvolvedores.

Verificação vs. Validação

Verificação: "Estamos construindo o produto corretamente?" Verifica se o produto foi construído de acordo com as especificações e requisitos.

Validação: "Estamos construindo o produto certo?" Valida se o produto atende às necessidades e expectativas do usuário e do negócio.

Exemplo de verificação: Verificar se um formulário de login tem os campos email e senha conforme especificado.

Exemplo de validação: Validar se o processo de login é intuitivo e seguro o suficiente para os usuários.

Ciclo de Vida do Teste

Fases do Teste

O processo de teste segue um ciclo que se repete continuamente durante o desenvolvimento:

1. Planejamento

Definir estratégia de teste, identificar recursos necessários, criar cronograma e determinar critérios de entrada e saída.

2. Análise e Design

Analisar requisitos, identificar condições de teste, criar casos de teste e preparar dados de teste.

3. Implementação

Desenvolver e priorizar casos de teste, criar scripts de teste automatizados (se aplicável) e preparar ambiente de teste.

4. Execução

Executar casos de teste, registrar resultados, comparar resultados esperados com reais e reportar defeitos encontrados.

5. Avaliação dos Critérios de Saída e Relatório

Avaliar se os critérios de saída foram atendidos, criar relatórios de teste e fornecer feedback sobre a qualidade do software.

6. Atividades de Encerramento

Arquivar testes e ambiente, documentar lições aprendidas e preparar entregáveis finais.

Objetivos do Teste

Objetivos Primários

  • Encontrar defeitos: Identificar o maior número possível de bugs antes do lançamento
  • Garantir qualidade: Verificar se o software atende aos requisitos e padrões de qualidade
  • Fornecer informações: Fornecer feedback sobre a qualidade do software para stakeholders
  • Prevenir defeitos: Identificar problemas cedo para evitar defeitos futuros

Objetivos Secundários

  • Reduzir riscos de falhas em produção
  • Aumentar a confiança na qualidade do software
  • Fornecer informações para decisões de negócio (go/no-go para lançamento)
  • Cumprir requisitos contratuais ou regulatórios
