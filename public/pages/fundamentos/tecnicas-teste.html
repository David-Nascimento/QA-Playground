Módulo 6: Técnicas de Teste

Aprenda técnicas práticas de teste como particionamento de equivalência, análise de valor limite, tabela de decisão, e técnicas de caixa branca para criar casos de teste eficazes e cobrir adequadamente o software.

O que são Técnicas de Teste?

Definição

Técnicas de teste são métodos sistemáticos usados para identificar condições de teste, casos de teste e dados de teste. Elas ajudam a garantir que os testes sejam eficientes e efetivos, cobrindo o máximo possível de cenários com um número razoável de casos de teste.

Usar técnicas de teste adequadas ajuda a:

  • Reduzir o número de testes necessários mantendo boa cobertura
  • Identificar casos de teste que realmente importam
  • Encontrar defeitos de forma mais eficiente
  • Garantir que diferentes tipos de erros sejam cobertos

Técnicas de Caixa Preta (Black Box)

As técnicas de caixa preta não requerem conhecimento do código interno. Elas se baseiam na especificação e no comportamento esperado do software.

Particionamento de Equivalência

Divide as entradas em grupos (partições) onde se espera que o comportamento seja o mesmo. Testamos um valor de cada partição, assumindo que todos os valores da mesma partição se comportarão de forma similar.

Como Aplicar

  1. Identifique o campo ou entrada a ser testado
  2. Divida as possíveis entradas em partições válidas e inválidas
  3. Escolha um valor representativo de cada partição para testar

Exemplo Prático

Para um campo de idade que aceita valores de 18 a 65:

  • Partição válida: 18-65 (teste com 30)
  • Partição inválida - abaixo: Menor que 18 (teste com 17)
  • Partição inválida - acima: Maior que 65 (teste com 66)
  • Partição inválida - tipo: Não numérico (teste com "abc")

Em vez de testar todos os valores possíveis (milhares), testamos apenas 4 valores representativos.

Análise de Valor Limite (Boundary Value Analysis)

Foca em testar valores nos limites das partições. Bugs frequentemente ocorrem nos limites porque desenvolvedores podem usar operadores incorretos (como > em vez de >=).

Como Aplicar

Para cada limite, teste:

  • O valor exatamente no limite
  • Um valor imediatamente abaixo do limite
  • Um valor imediatamente acima do limite

Exemplo Prático

Para um campo que aceita valores de 1 a 100:

  • Limite inferior: 0, 1, 2
  • Limite superior: 99, 100, 101

Isso cobre os pontos onde erros são mais prováveis de ocorrer.

Tabela de Decisão (Decision Table)

Útil quando há múltiplas condições que se combinam de diferentes formas para produzir diferentes resultados. Ajuda a garantir que todas as combinações possíveis sejam consideradas.

Como Aplicar

  1. Identifique todas as condições relevantes
  2. Liste todas as ações possíveis
  3. Crie uma tabela com todas as combinações de condições
  4. Identifique qual ação deve ocorrer para cada combinação
  5. Crie casos de teste para cada linha da tabela

Exemplo Prático

Regra de negócio: Desconto aplicado baseado em tipo de cliente e valor da compra:

Cliente VIP Valor > 1000 Desconto
Sim Sim 20%
Sim Não 10%
Não Sim 5%
Não Não 0%

Casos de Uso (Use Cases)

Testa fluxos de usuário completos do início ao fim. Foca em como o usuário interage com o sistema para atingir um objetivo específico.

Como Aplicar

  1. Identifique os principais fluxos de usuário
  2. Documente os passos do usuário
  3. Teste o fluxo completo
  4. Teste variações e caminhos alternativos

Exemplo Prático

Caso de uso: Usuário faz login e atualiza perfil:

  1. Acessar página de login
  2. Inserir credenciais válidas
  3. Ser redirecionado para dashboard
  4. Navegar para página de perfil
  5. Atualizar informações do perfil
  6. Salvar alterações
  7. Verificar se alterações foram salvas

Técnicas de Caixa Branca (White Box)

As técnicas de caixa branca requerem conhecimento do código interno. Elas focam em testar a estrutura e lógica do código.

Cobertura de Declarações (Statement Coverage)

Garante que cada linha de código seja executada pelo menos uma vez. É a forma mais básica de cobertura.

Exemplo

Para garantir 100% de cobertura de declarações, todos os caminhos do código devem ser executados pelo menos uma vez.

Cobertura de Decisões (Decision Coverage)

Garante que cada decisão (if, switch, while, etc.) seja testada com valores que resultem em true e false.

Exemplo

Para um if/else, você precisa de pelo menos dois testes: um onde a condição é verdadeira e outro onde é falsa.

Cobertura de Condições (Condition Coverage)

Garante que cada condição individual em expressões booleanas seja testada com valores true e false.

Exemplo

Para a expressão "if (A && B)", você precisa testar:

  • A = true, B = true
  • A = true, B = false
  • A = false, B = true
  • A = false, B = false

Quando Usar Cada Técnica

Particionamento de Equivalência

Use quando há muitos valores possíveis para uma entrada e você quer reduzir o número de testes mantendo boa cobertura.

Análise de Valor Limite

Use quando há limites numéricos ou limites de validade. Combine com particionamento de equivalência para melhor resultado.

Tabela de Decisão

Use quando há múltiplas condições que se combinam de forma complexa. Ajuda a garantir que não esquecemos nenhuma combinação.

Casos de Uso

Use para testar fluxos de usuário completos e garantir que o sistema funciona do ponto de vista do usuário final.

Técnicas de Caixa Branca

Use quando você tem acesso ao código e quer garantir cobertura específica. Geralmente usado mais por desenvolvedores, mas QAs também podem usar para validar.
