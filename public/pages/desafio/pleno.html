Desafio 1: Tabela com Paginação Dinâmica

Objetivo: Testar a navegação entre páginas de uma tabela paginada, validar consistência dos dados e gerenciar estados de botões de navegação.

Regras de Negócio

  • Paginação: Tabela deve ter controles de navegação (Primeira, Anterior, Próxima, Última)
  • Informação: Deve exibir página atual, total de páginas e total de itens
  • Estado dos Botões: Botão "Anterior" deve estar desabilitado na primeira página
  • Estado dos Botões: Botão "Próxima" deve estar desabilitado na última página
  • Dados: Cada página deve exibir quantidade fixa de itens (ex: 10 itens por página)
  • Consistência: Não deve haver duplicação de dados entre páginas
  • Atualização: Tabela deve atualizar após clicar em botão de navegação (pode haver delay)

Cenários de Teste

Cenário 1: Navegação Básica

O que fazer: Navegar para a próxima página e validar que os dados mudaram

Resultado Esperado: Dados da tabela são atualizados, informações de paginação são atualizadas

Cenário 2: Validação de Estado dos Botões

O que fazer: Na primeira página, verificar estado dos botões "Anterior" e "Primeira"

Resultado Esperado: Botões "Anterior" e "Primeira" devem estar desabilitados

Cenário 3: Navegação para Última Página

O que fazer: Clicar em "Última" e verificar estado dos botões

Resultado Esperado: Última página é exibida, botões "Próxima" e "Última" ficam desabilitados

Cenário 4: Validação de Dados entre Páginas

O que fazer: Navegar por todas as páginas e coletar dados de cada uma

Resultado Esperado: Não deve haver duplicação de dados entre páginas diferentes

Cenário 5: Navegação Sequencial

O que fazer: Navegar: Primeira → Próxima → Próxima → Anterior → Última → Anterior

Resultado Esperado: Cada navegação deve funcionar corretamente e dados devem ser atualizados

Como Procurar Elementos

  • Botão Próxima: data-testid="pagination-next" ou button[aria-label*="próxima"]
  • Botão Anterior: data-testid="pagination-prev" ou button[aria-label*="anterior"]
  • Botão Primeira: data-testid="pagination-first"
  • Botão Última: data-testid="pagination-last"
  • Informação Paginação: data-testid="pagination-info" ou elemento que mostra "Página X de Y"
  • Linhas da Tabela: tbody tr para contar itens na página atual
  • Verificar Desabilitado: element.get_attribute("disabled") ou element.is_enabled()

Instruções Passo a Passo

  1. Acesse a página Tabela com Paginação
  2. Observe as informações de paginação (página atual, total de páginas, total de itens)
  3. Na primeira página, verifique se botões "Anterior" e "Primeira" estão desabilitados
  4. Conte quantas linhas existem na página atual
  5. Clique em "Próxima" → Aguarde a tabela atualizar → Verifique que dados mudaram
  6. Verifique que botão "Anterior" agora está habilitado
  7. Navegue até a última página → Verifique que botões "Próxima" e "Última" ficam desabilitados
  8. Navegue por todas as páginas e valide que não há dados duplicados
  9. Teste navegação sequencial em ambas as direções

Exemplo de Automação

it('deve navegar entre páginas da tabela', () => {
  cy.visit('/pages/pleno/tabelas/dynamic-pagination.html')
  
  // Verifica estado inicial
  cy.get('[data-testid="pagination-prev"]').should('be.disabled')
  cy.get('[data-testid="pagination-first"]').should('be.disabled')
  
  // Navega para próxima página
  cy.get('[data-testid="pagination-next"]').click()
  cy.wait(500) // Aguarda atualização
  
  // Verifica que botão anterior está habilitado
  cy.get('[data-testid="pagination-prev"]').should('not.be.disabled')
  
  // Coleta dados da primeira página
  cy.get('tbody tr').then(($rows1) => {
    const dados1 = Array.from($rows1).map(row => row.textContent)
    
    // Navega para próxima
    cy.get('[data-testid="pagination-next"]').click()
    cy.wait(500)
    
    // Coleta dados da segunda página
    cy.get('tbody tr').then(($rows2) => {
      const dados2 = Array.from($rows2).map(row => row.textContent)
      
      // Valida que não há duplicação
      const duplicados = dados1.filter(d => dados2.includes(d))
      expect(duplicados.length).to.equal(0)
    })
  })
})

})

public void testNavegacaoPaginacao() {

    // Navega até última página

    btnUltima.click();
    wait.until(ExpectedConditions.not(ExpectedConditions.elementToBeClickable(btnProxima)));
    
    // Verifica que próxima está desabilitada
    assertFalse(btnProxima.isEnabled());
}

Desafio 2: Upload e Validação de Arquivos

Objetivo: Testar upload de arquivos com validação de formato, tamanho, múltiplos arquivos e feedback visual durante o processo.

Regras de Negócio

  • Formatos Permitidos: Apenas imagens (.jpg, .png, .gif) são aceitas
  • Tamanho Máximo: Arquivo não pode exceder 5MB
  • Múltiplos Arquivos: Sistema permite upload de até 5 arquivos simultaneamente
  • Feedback Visual: Deve exibir barra de progresso durante upload
  • Validação: Mensagens de erro devem aparecer para formatos inválidos ou tamanho excedido
  • Sucesso: Após upload bem-sucedido, nome do arquivo deve ser exibido
  • Estado: Botão de upload deve estar desabilitado durante o processo

Cenários de Teste

Cenário 1: Upload de Arquivo Válido

O que fazer: Fazer upload de uma imagem .jpg menor que 5MB

Resultado Esperado: Barra de progresso aparece, upload completa, nome do arquivo é exibido

Cenário 2: Upload de Formato Inválido

O que fazer: Tentar fazer upload de arquivo .exe ou .bat

Resultado Esperado: Mensagem de erro aparece: "Formato de arquivo não permitido"

Cenário 3: Upload de Arquivo Grande

O que fazer: Tentar fazer upload de arquivo maior que 5MB

Resultado Esperado: Mensagem de erro: "Arquivo excede o tamanho máximo de 5MB"

Cenário 4: Upload Múltiplos Arquivos

O que fazer: Selecionar 3 arquivos de imagem simultaneamente

Resultado Esperado: Todos os 3 arquivos são processados e nomes são exibidos

Cenário 5: Estado Durante Upload

O que fazer: Durante o upload, verificar estado do botão e barra de progresso

Resultado Esperado: Botão fica desabilitado, barra de progresso mostra progresso

Como Procurar Elementos

  • Campo Upload: input[type="file"] ou data-testid="input-upload"
  • Barra Progresso: data-testid="upload-progress" ou progress
  • Mensagem Sucesso/Erro: data-testid="upload-message"
  • Lista Arquivos: data-testid="uploaded-files" ou lista de elementos
  • Botão Upload: button[type="submit"] ou data-testid="btn-upload"

Instruções Passo a Passo

  1. Acesse a página Validação de Formatos
  2. Clique no campo de upload e selecione uma imagem .jpg válida
  3. Observe se barra de progresso aparece e se botão fica desabilitado
  4. Aguarde upload completar → Verifique se nome do arquivo é exibido
  5. Tente fazer upload de arquivo .exe → Verifique mensagem de erro
  6. Tente fazer upload de arquivo maior que 5MB → Verifique mensagem de erro
  7. Selecione múltiplos arquivos (até 5) → Verifique se todos são processados

Desafio 3: Drag and Drop de Elementos

Objetivo: Testar funcionalidade de arrastar e soltar elementos entre áreas diferentes, validando estados e animações.

Regras de Negócio

  • Elemento Arrastável: Deve ter atributo draggable="true"
  • Área de Destino: Deve aceitar drop e ter feedback visual quando elemento está sobre ela
  • Movimento: Elemento deve ser removido da origem e adicionado ao destino
  • Área Inválida: Tentar arrastar para área não permitida deve ser rejeitado
  • Múltiplos Elementos: Sistema pode permitir arrastar múltiplos elementos sequencialmente
  • Feedback Visual: Durante o drag, elemento deve ter estado visual diferente (opacidade, cursor)

Cenários de Teste

Cenário 1: Drag and Drop Básico

O que fazer: Arrastar elemento da área origem para área destino

Resultado Esperado: Elemento aparece na área destino e desaparece da origem

Cenário 2: Múltiplos Elementos

O que fazer: Arrastar 3 elementos sequencialmente para o destino

Resultado Esperado: Todos os 3 elementos aparecem na área destino

Cenário 3: Área Inválida

O que fazer: Tentar arrastar elemento para área que não aceita drop

Resultado Esperado: Elemento retorna para origem ou é rejeitado visualmente

Como Procurar Elementos

  • Elemento Arrastável: data-testid="drag-source" ou [draggable="true"]
  • Área Destino: data-testid="drop-target" ou elemento com evento ondrop
  • Verificar Posição: Após drop, verificar se elemento está dentro do container destino

Instruções Passo a Passo

  1. Acesse a página Drag and Drop
  2. Identifique o elemento que pode ser arrastado (drag source)
  3. Identifique a área de destino (drop target)
  4. Arraste o elemento da origem para o destino
  5. Verifique se elemento aparece na área destino
  6. Verifique se elemento desapareceu da área origem
  7. Teste arrastar múltiplos elementos sequencialmente

Exemplo de Automação

it('deve arrastar e soltar elemento', () => {

Desafio 4: Interação com Slider (Range Input)

Objetivo: Testar manipulação de slider, validar valores, limites e atualização em tempo real.

Regras de Negócio

  • Limites: Slider tem valor mínimo e máximo definidos (ex: 0 a 100)
  • Valor Inicial: Slider pode ter valor padrão ao carregar
  • Atualização: Valor exibido deve atualizar em tempo real durante o arraste
  • Precisão: Slider pode ter step (incremento) definido (ex: step="1" ou step="10")
  • Feedback Visual: Deve haver indicador visual do valor atual

Cenários de Teste

Cenário 1: Mover para Valor Mínimo

O que fazer: Arrastar slider para o valor mínimo

Resultado Esperado: Valor exibido corresponde ao mínimo, slider não pode ir abaixo

Cenário 2: Mover para Valor Máximo

O que fazer: Arrastar slider para o valor máximo

Resultado Esperado: Valor exibido corresponde ao máximo, slider não pode ir acima

Cenário 3: Valor Intermediário

O que fazer: Arrastar slider para um valor intermediário (ex: 50)

Resultado Esperado: Valor exibido corresponde à posição do slider

Como Procurar Elementos

  • Slider: input[type="range"] ou data-testid="slider-range"
  • Valor Exibido: data-testid="slider-value" ou elemento que mostra o valor
  • Atributos: min, max, value, step

Instruções Passo a Passo

  1. Acesse a página Slider
  2. Observe o valor inicial do slider
  3. Arraste o slider para a esquerda (valor mínimo) → Verifique valor exibido
  4. Arraste o slider para a direita (valor máximo) → Verifique valor exibido
  5. Arraste para um valor intermediário → Verifique se valor atualiza em tempo real
  6. Teste valores específicos usando setas do teclado (se suportado)

Exemplo de Automação

it('deve manipular slider', () => {
  cy.visit('/pages/pleno/interacoes/slider.html')
  
  cy.get('input[type="range"]').then($slider => {
    const min = parseInt($slider.attr('min'))
    const max = parseInt($slider.attr('max'))
    
    // Move para mínimo
    cy.wrap($slider).invoke('val', min).trigger('input')
    cy.get('[data-testid="slider-value"]').should('contain', min)
    
    // Move para máximo
    cy.wrap($slider).invoke('val', max).trigger('input')
    cy.get('[data-testid="slider-value"]').should('contain', max)
  })
})

  // Move para mínimo

  await expect(page.getByTestId('slider-value')).toContainText(min)
  
  // Move para máximo
  await slider.fill(max)
  await expect(page.getByTestId('slider-value')).toContainText(max)
})

Desafio 5: Ordenação de Colunas em Tabela

Objetivo: Testar ordenação ascendente e descendente de colunas, validar indicadores visuais e consistência dos dados.

Regras de Negócio

  • Ordenação: Clicar no cabeçalho ordena ascendente, segundo clique ordena descendente
  • Indicador Visual: Deve mostrar seta para cima (asc) ou para baixo (desc) na coluna ordenada
  • Múltiplas Colunas: Apenas uma coluna pode estar ordenada por vez
  • Dados: Ordenação deve ser aplicada corretamente (numérica, alfabética, data)
  • Atualização: Tabela deve atualizar após clicar (pode haver delay de animação)

Cenários de Teste

Cenário 1: Ordenação Ascendente

O que fazer: Clicar no cabeçalho de uma coluna pela primeira vez

Resultado Esperado: Dados são ordenados de A-Z ou menor para maior, seta para cima aparece

Cenário 2: Ordenação Descendente

O que fazer: Clicar novamente no mesmo cabeçalho

Resultado Esperado: Dados são ordenados de Z-A ou maior para menor, seta para baixo aparece

Cenário 3: Mudança de Coluna

O que fazer: Com uma coluna ordenada, clicar em outra coluna

Resultado Esperado: Nova coluna é ordenada, indicador visual muda para nova coluna

Cenário 4: Validação de Ordenação

O que fazer: Após ordenar, coletar valores da coluna e verificar ordem

Resultado Esperado: Valores estão na ordem correta (ascendente ou descendente)

Como Procurar Elementos

  • Cabeçalho Ordenável: th[data-sortable="true"] ou data-testid="sort-header"
  • Indicador Asc: data-testid="sort-asc" ou classe CSS específica
  • Indicador Desc: data-testid="sort-desc" ou classe CSS específica
  • Linhas Após Ordenação: tbody tr para coletar valores ordenados

Instruções Passo a Passo

  1. Acesse a página Tabela Ordenável
  2. Observe a ordem inicial dos dados na tabela
  3. Clique no cabeçalho da primeira coluna ordenável
  4. Verifique se dados são ordenados ascendente e seta para cima aparece
  5. Clique novamente no mesmo cabeçalho → Verifique ordenação descendente
  6. Clique em outra coluna ordenável → Verifique que indicador muda para nova coluna
  7. Valide que dados estão corretamente ordenados comparando valores

Exemplo de Automação

it('deve ordenar coluna da tabela', () => {
  cy.visit('/pages/pleno/tabelas/ordenaveis.html')
  
  // Coleta valores antes da ordenação
  cy.get('tbody tr td:nth-child(1)').then($cells => {
    const valoresAntes = Array.from($cells).map(cell => cell.textContent.trim())
    
    // Clica no cabeçalho para ordenar
