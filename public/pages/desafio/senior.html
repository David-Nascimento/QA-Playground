Desafio 1: Interação com Shadow DOM

Objetivo: Localizar e interagir com elementos dentro de Shadow DOM encapsulado, que não são acessíveis por seletores CSS tradicionais. Este é um dos desafios mais complexos de automação web moderna.

Regras de Negócio

  • Encapsulamento: Elementos dentro de Shadow DOM não são acessíveis por seletores CSS/XPath tradicionais
  • Shadow Root: Deve ser acessado via element.shadowRoot (apenas se mode='open')
  • Shadow DOM Fechado: Se mode='closed', acesso é ainda mais limitado e requer estratégias alternativas
  • Nested Shadow DOM: Pode haver Shadow DOMs aninhados (Shadow DOM dentro de Shadow DOM)
  • Interação: Após localizar elemento dentro do Shadow Root, interações funcionam normalmente
  • Desafio Extra: Criar função helper reutilizável que funcione com qualquer nível de aninhamento

Cenários de Teste

Cenário 1: Falha com Seletores Tradicionais

O que fazer: Tentar localizar elemento dentro do Shadow DOM usando seletores CSS tradicionais

Resultado Esperado: Seletores tradicionais falham (elemento não encontrado)

Validação: Confirme que driver.find_element(By.CSS_SELECTOR, "button") não encontra o botão dentro do Shadow DOM

Cenário 2: Acesso via Shadow Root (Open Mode)

O que fazer: Acessar Shadow Root e localizar elemento dentro dele

Resultado Esperado: Elemento é encontrado e pode ser interagido

Desafio: Criar função que verifica se Shadow Root está aberto antes de acessar

Cenário 3: Interação com Elementos Encapsulados

O que fazer: Clicar em botão e preencher input dentro do Shadow DOM

Resultado Esperado: Interações funcionam normalmente após acesso correto ao Shadow Root

Cenário 4: Shadow DOMs Aninhados

O que fazer: Acessar elemento dentro de Shadow DOM que está dentro de outro Shadow DOM

Resultado Esperado: Deve acessar cada nível sequencialmente: shadowRoot1 → shadowRoot2 → elemento

Desafio Avançado: Criar função recursiva que encontre elemento em qualquer nível de aninhamento

Cenário 5: Validação de Estados

O que fazer: Validar estado (checked, value, text) de elementos dentro do Shadow DOM

Resultado Esperado: Estados podem ser lidos normalmente após acesso correto

Como Procurar Elementos

  • Host Element: data-testid="shadow-host" ou elemento custom que contém Shadow DOM
  • Acesso Shadow Root: element.shadowRoot (JavaScript) ou via executeScript
  • Elemento dentro Shadow: shadowRoot.querySelector('button')
  • Verificar Mode: element.shadowRoot.mode retorna 'open' ou 'closed'
  • Múltiplos Elementos: shadowRoot.querySelectorAll('input')

Instruções Passo a Passo

  1. Acesse a página Shadow DOM
  2. Use DevTools para inspecionar e identificar o elemento host que contém Shadow DOM
  3. Tente localizar botão usando driver.find_element(By.CSS_SELECTOR, "button") → Deve falhar
  4. Acesse o Shadow Root: shadowHost = driver.find_element(By.ID, "shadow-host")
  5. Use JavaScript executor para acessar: shadowRoot = driver.execute_script("return arguments[0].shadowRoot", shadowHost)
  6. Localize elemento dentro: button = driver.execute_script("return arguments[0].querySelector('button')", shadowRoot)
  7. Interaja com o elemento: driver.execute_script("arguments[0].click()", button)
  8. Valide que a interação funcionou verificando mudanças no resultado
  9. Se houver Shadow DOMs aninhados, repita o processo para cada nível

// Helper function para Shadow DOM aninhado
function findInShadow(selector, shadowHost) {
  const shadowRoot = shadowHost.shadowRoot
  if (!shadowRoot) return null
  
  let element = shadowRoot.querySelector(selector)
  if (element) return element
  
  // Busca recursivamente em Shadow DOMs aninhados
  const nestedShadows = shadowRoot.querySelectorAll('*')
  for (let el of nestedShadows) {
    if (el.shadowRoot) {
      element = findInShadow(selector, el)
      if (element) return element
    }
  }
  return null
}

// Helper method para Shadow DOM aninhado
public WebElement findInShadowDOM(String selector, WebElement host) {
    JavascriptExecutor js = (JavascriptExecutor) driver;
    Object shadowRoot = js.executeScript("return arguments[0].shadowRoot", host);
    if (shadowRoot == null) return null;
    
    WebElement element = (WebElement) js.executeScript(
        "return arguments[0].querySelector(arguments[1])", shadowRoot, selector);
    if (element != null) return element;
    
    // Busca recursivamente em Shadow DOMs aninhados
    List nested = (List) js.executeScript(
        "return Array.from(arguments[0].querySelectorAll('*'))", shadowRoot);
    for (WebElement el : nested) {
        if (js.executeScript("return arguments[0].shadowRoot", el) != null) {
            element = findInShadowDOM(selector, el);
            if (element != null) return element;
        }
    }
    return null;
}

Desafio 2: Performance em Large DOM

Objetivo: Testar performance e localização de elementos em uma página com milhares de elementos DOM. Otimizar seletores e estratégias para garantir testes rápidos e confiáveis mesmo em DOMs massivos.

Regras de Negócio

  • Tamanho do DOM: Página contém 10.000+ elementos DOM
  • Performance: Localização de elemento deve ocorrer em menos de 1 segundo
  • Elementos Fora da Viewport: Muitos elementos não estão visíveis inicialmente
  • Scroll Necessário: Elementos podem estar em qualquer posição da página
  • Seletores: Seletores genéricos (div, span) retornam milhares de elementos e são lentos
  • Otimização: data-testid é significativamente mais rápido que CSS/XPath genéricos
  • Desafio Extra: Criar benchmark comparando performance de diferentes estratégias de localização

Cenários de Teste

Cenário 1: Medição de Performance

O que fazer: Medir tempo de localização usando diferentes seletores

Resultado Esperado: data-testid deve ser mais rápido que CSS genérico, que é mais rápido que XPath complexo

Desafio: Criar teste que compare: div[data-testid="item-5000"] vs div:nth-child(5000) vs //div[5000]

Cenário 2: Localização de Elemento Específico

O que fazer: Localizar elemento específico (ex: item-5000) entre 10k+ elementos

Resultado Esperado: Elemento é encontrado em menos de 1 segundo usando seletor otimizado

Cenário 3: Elemento Fora da Viewport

O que fazer: Localizar elemento que não está visível inicialmente (requer scroll)

Resultado Esperado: Elemento é encontrado, scroll é executado, elemento fica visível

Cenário 4: Múltiplas Localizações

O que fazer: Localizar 10 elementos diferentes espalhados pelo DOM

Resultado Esperado: Todas as localizações completam em tempo aceitável

Desafio: Otimizar para que todas as 10 localizações completem em menos de 5 segundos total

Como Procurar Elementos

  • data-testid (Recomendado): div[data-testid="item-5000"] - Mais rápido
  • CSS Específico: div.item-class[data-id="5000"] - Rápido se específico
  • XPath: //div[@data-testid='item-5000'] - Mais lento, evite se possível
  • Evitar: div, span, //div - Retornam milhares de elementos
  • Scroll: element.scrollIntoView() ou driver.execute_script("arguments[0].scrollIntoView()", element)
  • Filtrar Visibilidade: Use is_displayed() após find_elements() se necessário

Instruções Passo a Passo

  1. Acesse a página Large DOM
  2. Use DevTools Performance tab para medir tempo de carregamento da página
  3. Meça tempo de localização com seletor genérico: driver.find_elements(By.TAG_NAME, "div") → Anote tempo
  4. Meça tempo com data-testid: driver.find_element(By.CSS_SELECTOR, "[data-testid='item-5000']") → Compare
  5. Localize elemento específico usando data-testid → Deve ser rápido
  6. Se elemento não estiver visível, use scrollIntoView() antes de interagir
  7. Teste localizar múltiplos elementos espalhados pelo DOM
  8. Crie benchmark comparando diferentes estratégias de localização

Desafio 3: Conteúdo Dinâmico com Loading Assíncrono

Objetivo: Testar elementos carregados dinamicamente via AJAX/fetch com delays variáveis e imprevisíveis. Criar estratégias robustas de wait que funcionem com qualquer tempo de resposta.

Regras de Negócio

  • Delay Variável: Tempo de carregamento pode variar de 1 a 10 segundos (aleatório)
  • Loading State: Spinner/loader aparece durante carregamento e desaparece quando completo
  • Múltiplos Carregamentos: Sistema pode ter múltiplos carregamentos simultâneos
  • Timeout: Se carregamento exceder 15 segundos, deve mostrar erro
  • Estado Inicial: Conteúdo não existe no DOM antes do carregamento
  • Desafio Extra: Criar wait customizado que funcione com delays variáveis sem usar time.sleep fixo

Cenários de Teste

Cenário 1: Carregamento com Delay Curto

O que fazer: Disparar carregamento e aguardar conteúdo aparecer (delay de 1-3 segundos)

Resultado Esperado: Spinner aparece, conteúdo carrega, spinner desaparece

Cenário 2: Carregamento com Delay Longo

O que fazer: Disparar carregamento e aguardar conteúdo aparecer (delay de 5-10 segundos)

Resultado Esperado: Wait explícito aguarda corretamente, conteúdo aparece

Cenário 3: Múltiplos Carregamentos Sequenciais

O que fazer: Disparar 3 carregamentos sequenciais, aguardando cada um completar

Resultado Esperado: Cada carregamento completa antes do próximo iniciar

Cenário 4: Validação Durante Loading

O que fazer: Durante o carregamento, verificar que spinner está visível e conteúdo não existe

Resultado Esperado: Spinner visível, conteúdo ausente do DOM

Cenário 5: Timeout (Negativo)

O que fazer: Simular timeout (se possível) ou aguardar tempo máximo

Resultado Esperado: Mensagem de erro aparece após timeout

Como Procurar Elementos

  • Spinner: data-testid="loading-spinner" ou elemento com classe "loading"
  • Conteúdo Dinâmico: data-testid="dynamic-content" ou container que recebe conteúdo
  • Botão Trigger: data-testid="btn-load" ou botão que dispara carregamento
  • Mensagem Erro: data-testid="error-message" para timeouts

Instruções Passo a Passo

  1. Acesse a página Conteúdo Dinâmico
  2. Verifique que o conteúdo dinâmico não existe inicialmente no DOM
  3. Clique no botão que dispara carregamento
  4. Verifique que spinner aparece imediatamente
  5. Use wait explícito para aguardar conteúdo aparecer (não use time.sleep fixo)
  6. Valide que spinner desaparece quando conteúdo é carregado
  7. Valide que conteúdo foi carregado corretamente
  8. Teste múltiplos carregamentos sequenciais

Desafio 4: Interação com Iframe e Iframes Aninhados

Objetivo: Localizar e interagir com elementos dentro de iframes, incluindo iframes aninhados. Gerenciar mudanças de contexto corretamente para evitar erros de localização.

Regras de Negócio

  • Isolamento: Elementos dentro do iframe não são acessíveis do contexto principal
  • Mudança de Contexto: Deve mudar para o iframe antes de localizar elementos dentro dele
  • Retorno: Deve voltar ao contexto principal após interações no iframe
  • Iframes Aninhados: Pode haver iframe dentro de iframe, requerendo múltiplas mudanças de contexto
  • Armadilha: Esquecer de voltar ao contexto principal causa falhas em testes subsequentes
  • Desafio Extra: Criar context manager (Python) ou try-finally que garanta retorno ao contexto principal

Cenários de Teste

Cenário 1: Falha sem Mudança de Contexto

O que fazer: Tentar localizar elemento dentro do iframe sem mudar contexto

Resultado Esperado: Elemento não é encontrado (NoSuchElementException)

Cenário 2: Interação com Iframe Simples

O que fazer: Mudar contexto, localizar e interagir com elemento, voltar ao contexto principal

Resultado Esperado: Interação funciona corretamente, contexto principal é restaurado

Cenário 3: Iframes Aninhados

O que fazer: Acessar elemento dentro de iframe que está dentro de outro iframe

Resultado Esperado: Deve mudar contexto sequencialmente: principal → iframe1 → iframe2

Desafio: Criar função que encontre e acesse iframe aninhado automaticamente

Cenário 4: Múltiplos Iframes na Página

O que fazer: Interagir com elementos em diferentes iframes na mesma página

Resultado Esperado: Deve mudar contexto para cada iframe antes de interagir

Como Procurar Elementos

  • Iframe: iframe ou data-testid="iframe-container"
  • Mudar Contexto: driver.switch_to.frame(iframe_element) ou driver.switch_to.frame("iframe-id")
  • Voltar Principal: driver.switch_to.default_content()
  • Voltar Um Nível: driver.switch_to.parent_frame() (para iframes aninhados)
  • Elemento Dentro Iframe: Após mudar contexto, localize normalmente

public void withNewWindow(Runnable action) {
    String original = driver.getWindowHandle();
    try {
        action.run();
    } finally {
        // Fecha todas as janelas exceto original
        Set allWindows = driver.getWindowHandles();
        for (String window : allWindows) {
            if (!window.equals(original)) {
                driver.switchTo().window(window);
                driver.close();
            }
        }
        driver.switchTo().window(original);
    }
}

Como Procurar Elementos

  • Alternativa 1: button[type="submit"][class="btn-primary"] (atributos estáticos)
  • Alternativa 2: //button[contains(text(), 'Salvar')] (XPath com texto)
  • Alternativa 3: //form//button[@type='submit'] (XPath relativo)

Desafio 9: Captura e Validação de Erros JavaScript

Objetivo: Detectar, capturar e validar erros JavaScript que ocorrem durante execução de testes. Criar sistema de monitoramento de erros para garantir qualidade.

Regras de Negócio

  • Tipos de Erro: ReferenceError, TypeError, SyntaxError, etc.
  • Níveis de Log: SEVERE (erros críticos), WARNING (avisos), INFO (informações)
  • Erros Esperados: Alguns erros podem ser esperados em testes negativos
  • Filtragem: Deve filtrar erros esperados dos erros reais
  • Reporte: Todos os erros devem ser reportados para análise
  • Desafio Extra: Criar helper que capture, filtre e reporte erros automaticamente

Cenários de Teste

Cenário 1: Capturar Erros SEVERE

Resultado Esperado: Apenas erros críticos são capturados

Cenário 2: Validar Ausência de Erros

Resultado Esperado: Lista de erros SEVERE está vazia

Cenário 3: Filtrar Erros Esperados

Resultado Esperado: Apenas erros não esperados são reportados

Cenário 4: Captura via CDP

O que fazer: Usar Chrome DevTools Protocol para capturar exceptions

Resultado Esperado: Erros são capturados em tempo real via CDP

Como Procurar Elementos

  • Browser Logs: driver.get_log('browser') retorna logs do console
  • Filtrar SEVERE: Filtrar logs por nível 'SEVERE'
  • CDP Runtime: Runtime.enable para capturar exceptions
  • window.onerror: Verificar via JavaScript se há erros não tratados

Instruções Passo a Passo

  1. Acesse a página JavaScript Error

  4. Obtenha logs: logs = driver.get_log('browser')

  6. Valide que não há erros (ou que erros esperados são capturados)

Desafio 10: Fluxo de Autenticação OAuth2

Objetivo: Testar fluxo completo de autenticação OAuth2 incluindo redirecionamentos, autorização, tokens e estados. Este é um dos desafios mais complexos de automação web.

Regras de Negócio

  • Fluxo OAuth2: Login → Redirecionamento → Autorização → Callback → Token → Autenticado
  • Redirecionamentos: Múltiplos redirecionamentos entre aplicação e provider
  • State Parameter: Parâmetro state deve ser validado para prevenir CSRF
  • Tokens: Access token e refresh token devem ser armazenados corretamente
  • Timeouts: Cada etapa pode ter timeout diferente
  • Mocks: Para testes estáveis, considere mockar o provider OAuth2
  • Desafio Extra: Criar função que gerencie todo o fluxo OAuth2 automaticamente

Cenários de Teste

Cenário 1: Iniciar Fluxo OAuth2

O que fazer: Clicar em botão de login OAuth2 e aguardar redirecionamento

Resultado Esperado: Redirecionamento para página de autorização do provider

Cenário 2: Autorização no Provider

O que fazer: Preencher credenciais e autorizar acesso

Resultado Esperado: Provider redireciona de volta com código de autorização

Cenário 3: Validação de Token

O que fazer: Validar que token foi recebido e armazenado (localStorage/cookie)

Resultado Esperado: Token existe e usuário está autenticado

Cenário 4: Negação de Autorização

O que fazer: Negar autorização no provider

Resultado Esperado: Redirecionamento de volta com erro, usuário não autenticado

Cenário 5: Validação de State

O que fazer: Validar que parâmetro state é preservado durante o fluxo

Resultado Esperado: State no callback corresponde ao state inicial

Como Procurar Elementos

  • URL Monitoring: Monitorar driver.current_url para detectar redirecionamentos
  • URL Parameters: Extrair code, state, error da URL de callback
  • LocalStorage: driver.execute_script('return localStorage.getItem("token")')
  • Cookies: driver.get_cookies() para verificar cookies de sessão
  • Wait for URL: Aguardar URL conter 'callback' ou 'authorize'

Instruções Passo a Passo

  1. Acesse a página OAuth2 Providers
  2. Salve URL inicial e state (se visível)
  3. Clique no botão de login OAuth2
  4. Aguarde redirecionamento: wait.until(lambda d: 'authorize' in d.current_url)
  5. Na página de autorização, preencha credenciais (se simulado)
  6. Clique em "Autorizar"
  7. Aguarde redirecionamento de volta: wait.until(lambda d: 'callback' in d.current_url)
  8. Extraia código/token da URL: code = parse_qs(urlparse(driver.current_url).query)['code'][0]
  9. Valide token em localStorage ou cookies
  10. Valide que usuário está autenticado (elementos específicos aparecem)

@Test
public void testOAuth2Flow() {
    driver.get("http://localhost/pages/senior/dinamicos/oauth2-providers.html");
    WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(30));
    
    // Clica login
    driver.findElement(By.cssSelector("[data-testid='btn-oauth-login']")).click();
    
    // Aguarda redirecionamento para authorize
    wait.until(ExpectedConditions.urlContains("authorize"));
    
    // Preenche credenciais
    driver.findElement(By.name("username")).sendKeys("user");
    driver.findElement(By.name("password")).sendKeys("pass");
    driver.findElement(By.cssSelector("button[type='submit']")).click();
    
    // Aguarda callback
    wait.until(ExpectedConditions.urlContains("callback"));
    String currentUrl = driver.getCurrentUrl();
    assertTrue(currentUrl.contains("code="));
    
    // Extrai código
    String code = extractCodeFromUrl(currentUrl);
    assertNotNull(code);
    
    // Valida token
    JavascriptExecutor js = (JavascriptExecutor) driver;
    String token = (String) js.executeScript("return localStorage.getItem('token')");
    assertNotNull(token);
    
    // Valida autenticado
    WebElement authenticated = driver.findElement(By.cssSelector("[data-testid='user-authenticated']"));
    assertTrue(authenticated.isDisplayed());
}

private String extractCodeFromUrl(String url) {
    // Extrai código da URL
    String[] parts = url.split("code=");
    if (parts.length > 1) {
        return parts[1].split("&")[0];
    }
    return null;
}
