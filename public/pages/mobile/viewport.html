    Guia do especialista

    No desktop, "tamanho da tela" é um número. No celular são vários: a área do layout, a área visível (que encolhe com o teclado e o zoom), a tela física e a densidade de pixels. Testar viewport é testar a relação entre eles.

    A meta viewport

    • Sem <meta name="viewport" content="width=device-width, initial-scale=1">, o celular renderiza como se tivesse ~980 px e encolhe tudo.
    • user-scalable=no e maximum-scale=1 impedem o zoom: falha no WCAG 1.4.4 (redimensionar texto).
    • Teste: a página abre legível sem zoom e permite ampliar até 200%.

    100vh no celular

    • Uma tela "100vh" fica mais alta que a área visível quando as barras do navegador aparecem: o botão do rodapé some atrás delas.
    • Use 100dvh (ou 100svh) e compare na tabela acima.
    • Teste: role a página no Chrome Android e no Safari iOS e observe elementos fixos no rodapé.

    Teclado virtual e notch

    • O teclado reduz o visual viewport, não o layout viewport. Campos no fim da página e barras fixas ficam escondidos.
    • Critério: com o teclado aberto, o campo em foco e o botão de enviar continuam visíveis.
    • Em aparelhos com notch, conteúdo encostado na borda precisa de env(safe-area-inset-*).

    Armadilhas comuns

    • Confiar só no "modo dispositivo" do DevTools: ele não simula barras do navegador, teclado virtual nem o motor do Safari.
    • Testar só retrato. Muitos usuários usam paisagem para vídeo, formulários longos e tablets.
    • Imagens nítidas no desktop e borradas no celular: DPR 3 pede imagens 3× maiores (srcset).
    • Detectar "celular" pela largura. Use (pointer: coarse) e (hover: none) para decidir interações.

    Automatize

    Os device descriptors definem largura, DPR, user agent e toque de uma vez. "Girar" o aparelho é trocar largura e altura.

    import { test, expect, devices } from '@playwright/test';

test.use({ ...devices['Pixel 7'] }); // 412 x 915, DPR 2.625, touch

test('retrato e paisagem', async ({ page }) => {
  await page.goto('/pages/mobile/viewport.html');
  await expect(page.getByTestId('viewport-orientation')).toContainText('Portrait');
  await expect(page.getByTestId('viewport-width')).toContainText('412');

  await page.setViewportSize({ width: 915, height: 412 }); // paisagem
  await expect(page.getByTestId('viewport-orientation')).toContainText('Landscape');
});

test('o dispositivo é de toque', async ({ page }) => {
  await page.goto('/pages/mobile/viewport.html');
  const toque = await page.evaluate(() => matchMedia('(pointer: coarse)').matches);
  expect(toque).toBe(true);
});

    Em aparelho ou emulador real, a orientação é do sistema operacional. No navegador do celular, use o contexto web (CHROMIUM ou WEBVIEW_*).

    import io.appium.java_client.android.AndroidDriver;
import org.openqa.selenium.ScreenOrientation;
import org.openqa.selenium.By;

driver.get("http://10.0.2.2:8000/pages/mobile/viewport.html"); // 10.0.2.2 = localhost do PC no emulador Android
WebElement orientacao = driver.findElement(By.cssSelector("[data-testid=viewport-orientation]"));
assertTrue(orientacao.getText().contains("Portrait"));

driver.rotate(ScreenOrientation.LANDSCAPE);
new WebDriverWait(driver, Duration.ofSeconds(5))
    .until(d -> orientacao.getText().contains("Landscape"));

driver.rotate(ScreenOrientation.PORTRAIT); // sempre devolva o aparelho ao estado inicial

    Informações para Testes

    Cenários de Teste:

    • Testar viewport em diferentes dispositivos (iPhone, Android, Tablet)
    • Validar orientação portrait e landscape
    • Testar media queries e breakpoints
    • Validar meta viewport tag
    • Testar zoom e scale do viewport
    • Validar adaptação de layout em diferentes resoluções
    • Testar device pixel ratio

    Elementos identificáveis:

    • data-testid="viewport-details" - Detalhes do viewport
    • data-testid="viewport-width" - Largura do viewport
    • data-testid="viewport-height" - Altura do viewport
    • data-testid="viewport-orientation" - Orientação atual
    • data-testid="adaptive-layout" - Layout adaptativo
    • data-testid="media-queries" - Media queries ativas
    • data-testid="orientation-info" - Informações de orientação

    Exemplos de Teste Automatizado:

    
# Appium + Ruby - Testar viewport e orientação
caps = {
  platformName: 'iOS',
  deviceName: 'iPhone SE',
  browserName: 'Safari',
  automationName: 'XCUITest'
}
driver = Appium::Driver.new({ caps: caps }).start_driver

driver.get('http://localhost:8080/pages/mobile/viewport.html')

# Verificar viewport portrait
viewport_width = driver.find_element(:css, '[data-testid="viewport-width"]')
expect(viewport_width.text).to include('375')

orientation = driver.find_element(:css, '[data-testid="viewport-orientation"]')
expect(orientation.text).to include('Portrait')

# Testar orientação landscape
driver.rotate(:landscape)
expect(orientation.text).to include('Landscape')

# Verificar media queries
mq_mobile = driver.find_element(:css, '[data-testid="mq-mobile"]')
expect(mq_mobile.css_value('background-color')).to be_truthy
