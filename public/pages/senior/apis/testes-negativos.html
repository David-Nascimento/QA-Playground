Testes Negativos (QA Mindset)

Exemplos práticos de cenários que devem ser testados: payload inválido, campos ausentes, injeção, valores extremos e mais.

Payload Inválido

Teste requisições com JSON malformado, estrutura incorreta ou tipos incompatíveis. API deve rejeitar com mensagem clara sem processar dados inválidos.

Cenários de teste:

  • JSON sintaticamente inválido: {"name": "João",} (vírgula trailing)
  • Tipos incompatíveis: {"age": "30"} quando espera number
  • Estrutura incorreta: {"user": []} quando espera objeto
  • JSON malformado: {"name": "João" (chave não fechada)
  • Caracteres de controle: {"name": "João\n\0"}
  • Encoding incorreto: bytes inválidos em UTF-8

Resultado esperado: 400 Bad Request com mensagem indicando erro de parsing, sem expor stack trace ou detalhes internos.

Campos Ausentes

Campos obrigatórios não enviados, campos opcionais com null vs ausente.

Testes:

  • Enviar sem campo obrigatório (ex: email ausente)
  • Enviar null em campo obrigatório
  • Enviar string vazia em campo obrigatório
  • Campo opcional ausente vs null (comportamento pode diferir)

Resultado esperado: 422 Unprocessable Entity com lista de campos ausentes.

Tipos Errados

String em campo numérico, array em campo string, objeto em campo primitivo.

Exemplos:

  • {"age": "trinta"} (string em campo number)
  • {"tags": "tag1"} (string em campo array)
  • {"id": {"value": 123}} (objeto em campo number)

Resultado esperado: 400 ou 422 com mensagem indicando tipo incorreto.

Token Expirado

Access token expirado, refresh token expirado, comportamento esperado.

Testes:

  • Usar access token após expiração (401)
  • Refresh token expirado (401, deve exigir novo login)
  • Token sem claim exp (deve rejeitar ou aceitar indefinidamente?)

Resultado esperado: 401 Unauthorized com mensagem sobre token expirado.

Permissões Insuficientes

Usuário sem role adequado, recurso de outro usuário, escopo OAuth insuficiente.

Testes:

  • Usuário comum tentando acessar recurso admin (403)
  • Usuário A tentando acessar recurso do usuário B (403)
  • Token OAuth sem escopo necessário (403)
  • API Key sem permissão para endpoint (403)

Resultado esperado: 403 Forbidden com mensagem clara sobre falta de permissão.

Injeção de Código e Path Traversal

Teste proteção contra injeção de código malicioso através de parâmetros não sanitizados. Valide que entrada do usuário não é executada como código.

Cenários de teste:

  • SQL Injection: ?filter=1' OR '1'='1 ou ?id=1; DROP TABLE users--
  • NoSQL Injection: {"$where": "this.password == this.username"} ou {"age": {"$gt": ""}}
  • XSS (Stored): {"name": ""} → Validar sanitização no armazenamento
  • Path Traversal: /api/files/../../../etc/passwd ou ?file=../../config.json
  • Command Injection: {"command": "rm -rf /"} ou ?exec=ls; cat /etc/passwd
  • LDAP Injection: ?filter=(cn=*)(|(userPassword=*))

Resultado esperado: 400 Bad Request com rejeição clara, ou sanitização adequada que remove/escapa caracteres perigosos. Nunca executar código fornecido pelo cliente.

Valores Extremos

Strings muito longas, números negativos onde não permitido, arrays vazios, null em campos obrigatórios.

Exemplos:

  • String de 10.000 caracteres em campo com limite de 100
  • Idade negativa: {"age": -5}
  • Array vazio em campo que requer pelo menos 1 item
  • Null em campo obrigatório
  • Número muito grande (overflow)

Resultado esperado: 422 com mensagem sobre limites ou formato inválido.

Encoding Incorreto

Caracteres especiais, emojis, encoding UTF-8 vs Latin-1.

Testes:

  • Caracteres especiais: {"name": "João & Maria"}
  • Emojis: {"name": "João 😀"}
  • Encoding misto (UTF-8 e Latin-1)
  • Caracteres de controle

Resultado esperado: Aceitar UTF-8 corretamente ou 400 se encoding inválido.

Headers Ausentes/Incorretos

Content-Type ausente, Accept incorreto, Authorization malformado.

Testes:

  • POST sem Content-Type (400)
  • Content-Type incorreto (ex: text/plain em endpoint JSON) (400 ou 415)
  • Accept: application/xml em endpoint JSON (406 ou 200 com formato diferente)
  • Authorization malformado (ex: "Bearer" sem token) (401)

Métodos Não Permitidos

POST em endpoint GET-only, DELETE sem permissão, OPTIONS não implementado.

Testes:

  • POST em endpoint que só aceita GET (405)
  • DELETE em recurso sem permissão (405 ou 403)
  • OPTIONS não implementado (405 ou 200 com Allow header)
  • Método customizado não suportado (405)

Resultado esperado: 405 Method Not Allowed com header Allow listando métodos válidos.

  • Campos problemáticos identificados
  • Não expõe informações sensíveis ou stack traces
