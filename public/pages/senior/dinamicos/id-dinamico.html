Informações para Testes

Desafios de Automação:

  • IDs que mudam a cada renderização ou interação
  • Seletores por ID não funcionam de forma confiável
  • Necessidade de estratégias alternativas de seleção
  • Validação de elementos mesmo com IDs variáveis
  • Testes que devem funcionar independente do ID

Estratégias Recomendadas:

  • Use data-testid para seleção estável (recomendado)
  • Prefira seletores por conteúdo quando apropriado
  • Use seletores CSS por posição relativa
  • Evite depender de IDs que mudam
  • Use XPath com funções de texto ou atributos estáveis

Exemplos de Teste Automatizado:


// Cypress - Usar data-testid (recomendado)
cy.get('[data-testid="elemento-dinamico"]').should('be.visible')
cy.get('[data-testid="btn-gerar-id"]').click()
cy.get('[data-testid="elemento-dinamico"]').should('be.visible') // Ainda funciona!

// Seleção por conteúdo
cy.contains('Elemento com ID Dinâmico').should('be.visible')
                

// Playwright - Usar data-testid
await page.getByTestId('elemento-dinamico').isVisible()
await page.getByTestId('btn-gerar-id').click()
await page.getByTestId('elemento-dinamico').isVisible() // Ainda funciona!

// Seleção por conteúdo
await expect(page.getByText('Elemento com ID Dinâmico')).toBeVisible()
                

// Selenium (Java) - Evitar seleção por ID dinâmico
// ❌ Ruim: driver.findElement(By.id("id-12345"));
// ✅ Bom: 
WebElement elemento = driver.findElement(By.cssSelector("[data-testid='elemento-dinamico']"));
driver.findElement(By.cssSelector("[data-testid='btn-gerar-id']")).click();
elemento = driver.findElement(By.cssSelector("[data-testid='elemento-dinamico']"));
assert elemento.isDisplayed();
                

# Capybara (Ruby) - Usar data-testid
expect(page).to have_css('[data-testid="elemento-dinamico"]', visible: true)
click_button '[data-testid="btn-gerar-id"]'
expect(page).to have_css('[data-testid="elemento-dinamico"]', visible: true)
